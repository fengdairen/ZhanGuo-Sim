# 27 · 国界绘制（城池归属的来源）

> 状态：2026-11-13 首版可用。工具：`dist/map-review/border_editor.html`，
> 生成器 `tools/pipeline/make_border_editor.py`，数据 `data/map/borders.json`。

---

## 1. 为什么单独做一个

城池编辑器原本兼管归属，结果它既改坐标又改国家，职责糊在一起。
现在拆开：

| 工具 | 只管 |
|---|---|
| **国界绘制器** | 画边界线 → 组成疆域 → **决定每座城属于哪个国家** |
| 城池编辑器 | 城池的**位置、人口、等级**（归属只读显示） |

## 2. 边界线怎么画

和画河一样：点着拉线，但**两端必须落在已有几何上**——

- 海岸线
- 河流
- 湖泊边界
- 其他边界线

端点会自动吸附（16 屏幕像素内），吸附成功显示绿点，没吸附上会提示。
画的时候圆点会跟着鼠标走，看得出会吸到哪。

`Enter` 收笔，`Esc` 取消。

## 3. 从边界线到疆域（核心）

现实里没人会把国界画得首尾严丝合缝，所以**缺口由水系自动补全**：

1. 把海岸线、河流、湖泊、**其他**边界线的所有折线建成一张图（顶点=节点，线段=边）；
2. 把选中边界线的两端**焊**到这张图上（在折线上插入投影点，相当于在河的该处开个口子）；
3. 端点两两之间跑 Dijkstra，取最短路径作为补线；
4. 贪心匹配端点，保证每条边界线只用一次、每个端点只连一次；
5. 沿「边界线 → 补线 → 边界线 → …」走一圈，回到起点即闭合；
6. 闭合环就是疆域多边形，算面积、判城邑内外。

关键设计：**选中的边界线不参与补全**——否则"补线"就是那条线自己，永远闭合不了。

内置测试（`tools/smoke/smoke_border_editor.js`）用一个人造方形水系验证：

| 场景 | 期望 | 结果 |
|---|---|---|
| 一条线横穿方形 | 补成上半（800×300=240 000 px²） | ✅ 240 000 |
| 两条线 + 两侧水系 | 成 800×200 的带（160 000 px²） | ✅ 160 000 |
| 端点在带内/带外 | 内外判定正确 | ✅ |
| 端点悬空 | 明确报错，不生成鬼东西 | ✅ |
| 疆域内城邑 | 自动改归属 | ✅ |

## 4. 定国家、落归属

疆域生成后在右侧面板：

- **名称**：给这块疆域起名
- **国家**：从 `state.json` 的九国里选（可留空）
- **地方**：可填宗族/家族，**留空 = 中央直辖**
- **应用归属**：把多边形内的所有城邑改成该国，并**直接写回 `data/map/ownership.csv`**

写盘格式（新增 `faction` 列）：

```csv
city_id,owner,faction,note
n0000,ZHAO,,          ← faction 空 = 中央直辖
n0001,ZHAO,晋中宗族,
n0002,,,              ← 未归属
```

WPF 控制台按 `cells[0]/cells[1]` 读，多一列不影响；但它自己保存时会写回三列（丢 `faction`），
`[待验证]` 需要同步改 `CityTab.SaveOwnership`。

## 5. 存盘

- 边界线与疆域：`data/map/borders.json`，改动 0.7 秒后 `POST /api/borders/save`
- 归属：`POST /api/ownership/save`
- 两者都保留 30 份备份在 `data/map/_editor/_backup/`

## 6. 现状与下一步

已可用：画线、吸附、补全、闭合、面积、内外判定、应用归属、自动存盘、撤销。

还没做：

- 疆域嵌套/重叠检查（两块疆域圈到同一座城）
- 边界线跨疆域共用（两国以同一条河为界）
- 地方势力的集中管理（目前是疆域上一个自由文本字段）
- 疆域顶点的手工微调
