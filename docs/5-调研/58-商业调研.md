# 09 · 商业调研：这个项目值不值得做

> 调研时间：2026-11-10
> 方法：以《历史模拟器：崇祯》为直接先例，以 AI 互动内容赛道为背景，以我们的文游模板为蓝本。
> 结论先行：**有商业价值，但不在"做一款游戏"，而在"把推演者从记账里解放出来"。前者已被证伪一次，后者还没人做。**

---

## 1. 先看先例：崇祯到底赚没赚钱

这是全篇最重要的数据，因为它直接推翻了"AI 历史推演游戏很火"的直觉。

| 指标 | 数值 | 来源 |
|---|---|---|
| 发售 | 2026-05-08，48 元买断 + Token 内购 | 官方 |
| **团队规模** | **不到 10 人** | 36氪 |
| 首月销量 | 约 **3 万份** | VGI 统计（转引） |
| 首月流水 | 约 **144 万元** | 按国区价格计 |
| **退款后开发者实收** | 约 **4 千多份 ≈ 20 万元** | 同上 |
| Steam 简中评论 | 1200+ 条，好评率 **54%**（一度 56%） | 36氪 |
| **次日留存** | **75.1%**，非工作日平均在线 **7 小时** | 制作组 |
| Token 定价 | 10 元 = 1000 点，开局送 4800 点；专家模式消耗是快速模式 **4 倍** | 官方 |
| 专家模式技术指标 | 推演前提正确率 **98.7%**，Function Call 匹配率 **99.86%** | 36氪 |
| 后续结局 | **6 月 25 日本体转免** + 开放自定义 API（BYOK） | 官方 |

### 1.0 一个被忽略的关键信号

**次日留存 75.1%、非工作日 7 小时在线。** 这不是一个"不好玩"的产品的数据。

`[判读]` 也就是说：**产品是成立的，死的是定价。**
玩家第二天还回来、还愿意泡七个小时——然后再也不回来了，因为账单。

这个区分很重要：它说明**需求侧没有问题**，问题在**成本转嫁给了用户**。

---

`[判读]` 首月净收约 20 万元。**这个数字单独看不算少**（下一节专门讨论），但对比"不到 10 人的团队 + 一年以上的开发周期 + 三测"，它是亏的。
评论区满是退款 tag，主要矛盾是 **Token 账单**（每小时 2–12 元）。

### 1.0.1 20 万到底算不算少？——修正我之前的草率说法

我先前说"连三人小团队半年工资都不够"，这句话**不精确**，因为当时不知道团队规模。现在数据齐了，重算：

| 框架 | 20 万意味着什么 |
|---|---|
| **一个人业余做** | 非常好。一个月回本，还赚。 |
| **两三人做半年** | 不错。人均 3–7 万，覆盖机会成本。 |
| **八九个人做一年以上**（实情） | **亏。** 按人均 1–1.5 万/月计，年成本 100–180 万。 |
| **对比流水** | 144 万 → 20 万，**86% 被退掉**。 |

所以准确的表述是：

> **20 万不多，但也不算笑话；真正难看的不是绝对值，是"卖出去 3 万份、只留下 4 千份"这个转化率。**

`[判读]` 换句话说：**问题不是"没人愿意买"，是"买了的人立刻后悔"。** 这是预期管理问题，不是需求问题。

`[判读]` 对我们的直接含义：**如果这件事由一两个人做，20 万/年的量级就已经是成功。** 商业判断必须和投入规模绑定，脱离团队规模谈"20 万很少"是不成立的。

### 1.1 但它证明了"需求存在"

首月 3 万份 + 次日留存 75.1% + 非工作日 7 小时，说明：**"用自然语言下诏、让 AI 推演历史"这个钩子，不但卖得动，而且留得住。**
失败的不是需求，是**交付方式**：
- 成本结构（每次交互都烧 token，买断价撑不住）
- 可靠性（AI 幻觉、记忆丢失、大臣死了还能上朝）
- 计费预期（Steam 玩家默认买断 = 一次付清）

`[判读]` 换句话说：**崇祯死在了商业模型和工程可靠性上，不是死在题材上。**

### 1.1.1 他们其实已经做出了对的技术，只是付不起

36氪披露：专家模式采用「**步进式状态机 + 底层数据库**」，达到 98.7% 的推演前提正确率、99.86% 的 Function Call 匹配率。

`[判读]` 这句话值得单独拎出来：**他们知道正确答案是什么**（状态机 + 数据库 + 可靠调用），也做到了。
但那一套的成本，是玩家不愿意付、团队也扛不住的。

这恰好回到我们前面 04 号文档的判断：**崇祯缺的不是"知道怎么做"，是"做得起"。**
而我们的方案（公式在 Excel 里、判定不烧 token）在结构上就便宜一个数量级。

### 1.2 行业侧的冷水

| 数据 | 含义 |
|---|---|
| Steam 2023–2026 共 5.36 万款游戏中，约 **1/3 使用 AI** | 供给爆炸 |
| AI 游戏占每月新增发行量的 **60–90%** | 增速几乎全靠 AI |
| 但 AI 游戏"销量达 3000 份"的比例，只有非 AI 游戏的 **55%** | **AI 标签是负向信号** |
| 有研究直接写："almost none of them make money" | 绝大多数不赚钱 |

`[判读]` 结论很反直觉：**AI 让做游戏变容易了，于是更难赚钱了。** 供给端洪水，需求端没涨。

**但注意两点：**

`[判读]` 资本在赌"平台"和"品类"，不是在赌"某一款历史推演游戏"。

### 2.1 一个几乎同款的先行者

《Chronos：历史的回响》——轻量 AI 历史推演文字互动游戏，vibe coding 出来的，玩家反馈积极。**但它的短板正是我们的长板：**

> "AI 判定的数值随机性强，不够合理。AI 有过度肯定玩家策略的倾向，在现实中难以实现的行为 AI 都会判定成功。"

`[判读]` 这段话值得抄下来贴在墙上。**整个品类的公敌是"AI 判定不可信"，而我们的模板恰好用公式解决了它。**

## 3. 我们的模板，商业上的独特之处

把三件事放在一起看：

| | 崇祯 | Chronos | **我们** |
|---|---|---|---|
| 判定 | 模型自由裁量 | 模型自由裁量 | **公式 + 判定修正** |
| 状态 | 字段 + 长上下文 | 无 | **结构化表** |
| 记账 | 模型写 | 模型写 | **Excel 公式** |
| 成本 | 3000 万 token/局 | 高 | **低（判定不烧 token）** |
| 可靠性 | 差 | 差 | **由公式保证** |

### 3.1 成本优势可以量化

崇祯：单局 3000 万 token。

我们的一回合（9 国，每国 1 条国策）：

```
解析国策   ：~3k token × 9 = 27k
生成回执   ：~2k token × 9 = 18k
─────────────────────────────
合计约 45k token/回合
```

按国产模型（千问/豆包级别）价格，**一回合成本约 0.1–0.3 元**。
100 回合 ≈ **10–30 元**。

对比崇祯的 2–12 元/小时——**低一到两个数量级**。

`[判读]` 原因很简单：**我们把"判定"这个最烧 token 的环节，交给了 Excel 公式。**

### 3.2 这是真正的差异化

> 别人卖的是"AI 会推演"，我们卖的是"**AI 不乱推演**"。

在一个"AI 判定不可信"是全品类公敌的市场里，**"可复现、可审计、不飘"本身就是卖点**。

## 4. 三条商业化路径

### 路径 A：自用（回本型）——推荐先做

- **卖什么**：不卖。服务你自己的群。
- **收益**：推演者每回合从 2–3 小时降到 20–30 分钟。
- **商业价值**：让"马力全开"成为可能——**开新团、加人、加频次**。
- **成本**：几乎为零。
- **评价**：⭐ 这是唯一确定有正收益的路径。

### 路径 B：卖工具给其他推演者（小而美）

- **卖什么**：SaaS / 一次性授权的"推演助手"。
- **卖给谁**：跑国策类文游的群主、跑团 GM、历史模拟爱好者社群。
- **定价**：按群收费，99–299 元/月，或 500–1500 元买断。
- **价值锚点**：省 8–12 小时/月，按 50 元/时算价值 400–600 元 → 定价有空间。
- **市场估算（粗）**：中文圈活跃的国策类文游群，乐观估 2000–5000 个。
  ```
  3000 群 × 99 元/月 × 12 ≈ 356 万元/年（乐观上限）
  ```
- **评价**：⭐ 能养活小团队，但天花板明确，且需要极强的"开箱即用"。

### 路径 C：做成产品（高风险）

- **卖什么**：Steam / 小游戏平台的成品游戏。
- **对标**：崇祯（失败）、Chronos（小规模）。
- **风险**：获客、发行、AI 标签负向、内容审核、单机退款。
- **评价**：⚠️ 除非已有社区基础，否则不建议作为第一条路径。

`[判读]` **A → B → C 是唯一合理的顺序**：先把自己的群跑顺，再把工具卖给同类群主，最后才考虑做面向大众的产品。
跳步的直接后果，崇祯已经演示过了。

## 5. 市场规模的诚实估计

| 层级 | 规模 | 依据 |
|---|---|---|
| 中文文游/跑团活跃玩家 | 数十万量级 | 社群化、分散、无权威统计 |
| 其中能持续开的国策类群 | **数千**（乐观） | 需长期在线推演者，门槛高 |
| 愿意为工具付费的群主 | **数百–一两千** | 参照跑团 GM 付费工具的渗透率 |
| 愿意为游戏付费的玩家 | 崇祯首月 3 万 | 但退款后仅 4 千 |

`[判读]` 这是一个**"小而深"的市场**：人不多，但痛得厉害，且几乎没人为他们做过工具。
**不是风口，是缝隙。** 缝隙的好处是没人抢，坏处是长不大。

## 6. 五个真实风险

| # | 风险 | 严重度 | 缓解 |
|---|---|---|---|
| 1 | **付费习惯弱**——文游圈长期"为爱发电"，跑团 GM 收费至今仍是争议话题 | 高 | 从"省时间"切入，不从"内容"切入 |
| 2 | **平台不闭环**——QQ 群内无法支付、无法跑程序 | 高 | 做成独立 Web 应用 + 导出回群 |
| 3 | **内容合规**——历史 + 国策 + 玩家自由输入，是审核高危区 | 高 | 关键词过滤 + 人工复核 + 规避近现代 |
| 4 | **先行者已转免**——崇祯本体免费 + BYOK，价格锚被拉到 0 | 中 | 我们不卖"AI"，卖"结算与审计" |
| 5 | **单人产能**——工具做出来还要有人维护、写文档、做客服 | 中 | 先服务 3–5 个种子群，验证再扩 |

## 7. 最小验证方案（MVP）

不要一上来做平台。用 2–3 周验证一件事：**推演者愿不愿意为"少改格子"付钱。**

**MVP 范围（只做三件事）：**

1. **国策 → 变更单**：玩家发一段文字，模型输出结构化 diff（改哪张表哪个格、改成多少、理由）。
2. **变更单 → 表格**：脚本套用 diff、跑公式、检查不变量（国库不为负、军队有驻地）。
3. **变更单 → 回执**：生成一段可直接贴回 QQ 群的奏报。

**明确不做：** 完整判定、战斗系统、多人协作、账号体系、支付。

**验证指标：**

| 指标 | 目标 |
|---|---|
| 推演者每回合耗时 | 从 2–3 小时降到 < 40 分钟 |
| diff 接受率（不改直接采纳） | > 70% |
| 数值错误率 | < 5% |
| 推演者主观意愿 | "愿意继续用" |

**成本**：模型调用约 30–100 元即可跑完一轮完整测试。

`[判读]` 如果"diff 接受率"上不去，说明问题不在模型，在**国策的输入格式**——那就需要约束玩家怎么写（比如规定"意图 / 对象 / 数量 / 期限"四段式）。这本身也是一个有价值的产品决策。

## 8. 结论

**三层回答：**

1. **它会赚钱吗？** 作为一款面向大众的游戏，大概率不会——崇祯已经用 20 万元实收证明了这一点。
2. **它有价值吗？** 有，而且是稀缺价值：**在一个"AI 判定不可信"是通病的品类里，我们手里有一份能算的账。**
3. **它值得开始吗？** 值得，但要按 **自用 → 卖工具 → 做产品** 的顺序，且第一步的验收标准是"你自己群的推演时间减半"，不是"卖出多少份"。

**一句话：**

> 这不是一个游戏创业项目，是一个**把已经跑通的桌面模型，变成软件的效率项目**。
> 它的天花板不高，但它的地板很稳——因为需求是真实的，而供给几乎为零。

---

## 9. 需要你确认的三件事

1. **你的群现在多少人、多久一回合？** 这决定了"省时间"的价值有多大。
2. **有没有其他群主向你打听过这套模板？** 如果有，路径 B 就已经有种子用户了。
3. **你愿意接受"永远长不大"吗？** 如果目标是养活一个小工具，这个项目很合适；如果目标是融资做大，那要换一套叙事（做成平台，卖引擎给其他题材）。
