# 12 · 工程结构：纯数据层 + 工作台 exe

> 状态：**M0 已完成并通过校验**（2026-11-10）
> 本文说明代码怎么分层、怎么跑、验证到了什么程度。

---

## 1. 为什么要重做数据层

Excel 的问题不是"不好用"，是**数据和显示耦合**：

- 公式和数据混在同一张表里，改一处不知道影响哪里
- 没有回合、没有事件日志，无法回放
- 税基引用是写死的行区间（`SUM(L43:L45)`），插一行就全错
- 读档可能触发副作用
- UI 就是 Excel 本身，无法做真正的 gameplay 界面

**结论：Excel 降级为"策划编辑工具"，运行期用纯数据结构。**

## 2. 分层

```
┌─────────────────────────────────────────────┐
│  ZhanGuo.Workbench (WPF exe)                │
│  只管显示与编辑，不认识公式                  │
└──────────────────┬──────────────────────────┘
                   │ 行对象（Row）双向绑定
┌──────────────────▼──────────────────────────┐
│  ZhanGuo.Core (纯 C# 类库，无 UI 依赖)       │
│  Model    ← 纯数据结构，可序列化             │
│  Rules    ← 公式，纯函数                     │
│  Serialization ← JSON 读写                   │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  data/state.json  ← 权威状态                 │
│  data/excel_reference.json ← Excel 缓存值，仅用于校验 │
└─────────────────────────────────────────────┘
```

**关键约束：Core 不引用任何 UI 程序集。**
所以它今天能被 WPF 工作台引用，明天也能被 Unity / Godot 引用，还能在命令行跑回归测试。

## 4. 数据流

```
备份.xlsm
   │  tools/export_state.py
   ▼
data/state.json  ──────────────┐
   │                           │
   │  工作台载入                │  校验器载入
   ▼                           ▼
编辑数值 → 公式重算 → 保存     与 excel_reference 对比
```

**公式只存在于一处**：`ZhanGuo.Core/Rules/Economy.cs`。
工作台不做任何算术，它只是把编辑写回模型，然后调用 `Economy.Totals()` 取结果。

## 6. 复现过程中发现的两处"隐藏数据"

这两处如果不挖出来，换任何语言重写都会算错。值得记下来。

### 6.1 人口权重是**逐行**的，不是全局常数

原表里每行都有 P/Q/R 三个权重，我最初以为是全局的 120/60/30。

实际：

| 国家 | 邑权重 |
|---|---|
| 鲁、齐、宋 | 30 |
| 魏·中山人 | **25** |
| 魏·上郡 | **20** |

修正后，魏国的人口从 4115 变回 4270，与 Excel 一致。

### 6.2 维护费成本是**逐部队**的，且逐国不同

原表三种维护费公式：

```
常规军：(步×60 + 甲×150 + 辅骑×180 + 车×300) × √(1+训练/100) × √战备 × 补给
独立骑兵：步×220 × ...
水师：  步×300 × ...
```

更麻烦的是：**越国的水师是 250，其他八国是 300。**

所以成本系数必须存成数据字段（`CostInfantry/CostElite/CostCavalry/CostChariots`），不能写死在代码里。
这也顺便让"不同国家的同兵种成本不同"成为一个可配置的设计空间。

## 7. 怎么运行

### 7.1 直接用（推荐）

双击：

```
dist\ZhanGuo.Workbench.exe
```

需要 **.NET 10 桌面运行时**（本机已装）。
若启动异常，同目录会生成 `workbench-error.log`。

### 7.2 从源码跑

```powershell
$env:DOTNET_CLI_HOME = "<repo>\.dotnet"
$env:NUGET_PACKAGES  = "<repo>\.nuget\packages"
dotnet run --project src\ZhanGuo.Workbench
```

### 7.3 跑公式校验

```powershell
dotnet run --project src\ZhanGuo.Verify -- <repo>            # 公式复现
dotnet run --project src\ZhanGuo.Verify -- <repo> changes    # 变更单行为
```

返回码 0 = 全部通过。

### 7.4 重新从 Excel 导出

```powershell
python tools\export_state.py
```

（会覆盖 `data/state.json`，注意先保存工作台里的改动。）

## 8. 数据怎么改：变更单，而不是改单元格

**这是本工程最重要的一条规则：任何页面都不直接写数值。**

所有数据改动都必须写成一条「变更」，写明**加减多少**、**事由是什么**，攒成一批后统一提交。

### 8.1 三种操作

| 操作 | 语义 | 例子 |
|---|---|---|
| **调整** | 在现有值上加减 | 魏·中山人 的 邑 **+3** |
| **转移** | 把离散量从 A 挪到 B | 魏·中山人 的 邑 **3** → 楚·（新建）中山人（新附） |
| **设定** | 直接赋值，仅在初始化/纠错时使用，日志里标记为「强改」 | 税率设为 0.8 |

`[判读]` 为什么不让人直接改？
因为"改成 3"和"加 3"在语义上完全不同：后者可重复、可叠加、可审计，前者一旦重放就会出错。**这正是崇祯「重复抄家」和「读档误清算」的根源。**

### 8.2 提交是原子的

一批变更里只要有一条不合法，**整批都不落地**，状态哈希不变。

### 8.3 校验规则

| 规则 | 行为 |
|---|---|
| 事由为空 | 拒绝 |
| 加减后越界（如邑变成负数） | 拒绝，并给出具体数值 |
| 转出量超过存量 | 拒绝 |
| 转移连续量（如国库存量） | 拒绝——连续量应改为两地各调整一次 |
| 目标不存在 | 拒绝；若为人群且勾选了「自动新建」，则新建一个同名新附人群 |

### 8.4 每次提交都会留痕

`data/events.jsonl` 追加一行：

```jsonc
{
  "turn": 0, "time": "2026-11-10T21:40:00+08:00",
  "beforeHash": "A1B2...", "afterHash": "C3D4...",
  "ops": [ { "kind": "Transfer", "target": {...}, "field": "Yi",
             "value": 3, "to": {...}, "memo": "割三邑入楚" } ],
  "deltas": [ { "where": "魏·中山人", "field": "邑（座）", "before": 33, "after": 30 } ]
}
```

这就是 M1 事件日志的第一块砖：**有前后哈希、有操作、有事由、有结果。**
理论上已经可以把整个状态从 genesis 重放到任意时刻。

### 8.5 页面分工

| 页签 | 作用 |
|---|---|
| **变更单** | 唯一的写入口。选对象 → 选字段 → 填加减量 → 填事由 → 加入 → 预览 → 提交 |
| 概览 / 财税 / 人口 / 军事 / 制度 / 时局 | 全部**只读**，供查看与核对 |

### 8.6 这一点和 LLM 的关系

`[判读]` 人和模型从此共用同一种输入格式：

```
人类：在界面上填一条 ChangeOp
LLM ：输出一条 ChangeOp 的 JSON
```

两者走的是同一套校验、同一套原子提交、同一条事件日志。
**这正是文档 10 里「模型只提议、代码裁决」的落地形态。**
等 M3 接 LLM 时，不需要另造一套协议。

### 8.7 顺手修掉的两个 Excel 毛病

1. 税基改为按人群 id 归组，插行不再错位。
2. 判定修正多了「事由」字段——每一笔修正都必须写清来由（现在更是强制）。

## 9. 下一步（M1）

工作台目前只是"能看能改"。M1 要让它"能跑"：

1. **回合推进**：`TurnResolver.Resolve(state, edicts)` 纯函数。
2. **事件日志**：每回合一条 JSON 记录，含前后哈希。
3. **回放**：从快照重放，验证无副作用。
4. **封驳**：资源不足时不静默通过，而是产出驳斥文本。

`[判读]` 顺序很重要：先让数字能被"推"一回合，再谈国策解析。
**M1 仍然不接 LLM。**
