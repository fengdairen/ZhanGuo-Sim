# 25 · 河流描迹：人工标注与数据格式

> 状态：**功能完备，可长期使用**（2026-11-12）
> 产物：`dist/river-editor/river_editor.html`（单文件描迹器）+ `启动描迹器.cmd`
> 数据：`data/map/rivers/river_segments.json`（v5：河段 + 海岸线 + 湖泽）
> 转换：`tools/rivers_from_editor.py` → 河网 / 河名 / 湖泽 / 海岸四份矢量层
> 地图：`python tools\build_sea_from_coast.py` + `make_vector_map.py` → `dist/map-vector/map.html`

---

## 1. 为什么要人工描

自动从位图里提河网，做了三版都不合格 `[已证实]`：

| 问题 | 证据 |
|---|---|
| 红色水面被描边盖断 | 红 469753 px 中有 6.2% 远离棕，断成一串虚线 |
| 描边是河的两条岸线 | 沿描边走线会把一条河画成两条，放大后河中央出现"劈缝" |
| 骨架走线有重复与错接 | 曾出现 3024px 的虚假直线、28% 的重复几何 |

根因不是算法调参，而是**源图只画了"看起来像河"的视觉符号**：
线条粗细、描边、断口都不是稳定的几何信息，靠灰度去反推"哪条是干流、谁汇入谁"，
误差不可避免。

所以改成：**主干与支流由人来定，机器只负责存储、拓扑与渲染。**

## 2. 怎么用

### 2.0 启动：双击 `启动描迹器.cmd`（推荐）

```
dist\river-editor\启动描迹器.cmd
```

它会起一个只监听 `127.0.0.1:8765` 的本地服务并自动打开浏览器。**改动 0.7 秒后自动写盘**
到 `data/map/rivers/river_segments.json`，右下角显示「本地服务 · 改动自动写盘」。

`[已证实]` 为什么必须这样：浏览器在 `file://` 下用 File System Access 绑定的文件句柄
**不跨会话保留**，每次重启浏览器都要重新选一次文件——这是规范行为，不是 bug。
把读写挪到本地服务进程之后，这个问题就不存在了。

`dist/river-editor/base_rivers.png` 是 `底图河道湖泊.png` 的副本（861 KB），体积原因**不进版本库**。
新克隆仓库后如果「河道参考图」图层是空的，手动复制一份即可：

```powershell
Copy-Item 底图河道湖泊.png dist\river-editor\base_rivers.png
```

服务端还做两件保险：

- 写入用**临时文件 + 原子替换**；
- 同一分钟内多次保存只留一份备份到 `data/map/rivers/_backup/`，保留最近 30 份。

**服务根目录是整个 `dist/`，不是 `dist/river-editor/`。**
因为页面里的美术底图是相对路径 `../map-review/ditu.png`（15 MB），
只服务 `river-editor/` 会让它 404——表现就是"勾了底图但一片空白"。
访问 `/` 会自动跳到 `/river-editor/`。

也可以直接双击 `river_editor.html`（无服务模式），此时回退到「绑定文件 / 浏览器缓存」，
数据只在缓存里，右下角会红字提示。这种模式下底图同样能用（同目录相对路径）。

| 操作 | 说明 |
|---|---|
| **单击** | 加点 |
| **双击 / 回车** | 收笔（同位置 340ms 内再点一次也算收笔） |
| **Backspace** | 退一个点；没有草稿时删除选中河段 |
| **空格/右键拖** | 平移 |
| **滚轮** | 以光标为中心缩放 |
| **1 / 2 / 3 / 4** | 画线时切换等级；选择模式下改**选中河段**的等级 |
| **0** | 全图 |
| **Ctrl+Z / Ctrl+Shift+Z** | 撤销 / 重做 |

**四个等级**：干流 / 一级支流 / 二级支流 / **运河**。运河用紫色虚线画，一眼区分人工水道。

`[已拍板]` **运河是连接件，不是支流**：它两头各接一条河（例如巢肥沟连施水与淮水），
所以数据结构是 `links`（端→河）而不是单一的 `parent`。运河不参与支流树的缩进，
也不会被算成谁的 N 级支流。

> `[已拍板 2026-11-11]` **等级不代表粗细。** 粗细只由水量决定——
> 淮河水量不如长江的支流，就该比它细。等级只回答一件事：**我是谁的支流**。

### 2.1 两级命名、水量、分段、认父

选中一条河段后，右侧「选中河段」面板给出：

| 项 | 作用域 | 说明 |
|---|---|---|
| **河名** | **整条河** | 同一条河的各段共用，改一次全部同步（第一级名字） |
| **段名** | **单段** | 可空；不填就显示「第 n 段」（第二级名字） |
| **水量 1–5** | **单段** | 极少 / 少 / 中 / 多 / 丰 —— **唯一决定线宽** |
| **等级** | 单段 | 由上级链自动推导（见下），也可手动改；运河是类型 |
| **端点接续** | 每一条河的**两端** | 每端一个「指定…」：点河道线 / 湖岸 / 海岸线都行，自动取最近的点。**接什么就是什么**，不需要先选"汇入还是入海" |
| **端点语义** | 每条河 | 河口端接河道=汇入、接湖=入湖、接海岸=入海；源头端接河道=岔出、接湖=出湖。**语义由端点位置决定，不由按钮决定** |
| **海岸线** | 全局 | 左侧「海岸」模式单独画；**选中后顶点可拖**（岛屿首尾联动，环不断）；拖动后接在上面的河口自动跟随 |
| **湖泽** | 全局 | 左侧「湖泽」模式画闭合水体：首尾落在河上会自动吸附并闭合 |
| **折叠** | 列表 | 点河名前的 ▾/▸ 折叠整条水系（含支流）；顶部「折叠 / 展开」一键全收 |
| **流向** | 单段 | 「反向」或按 `R` 反转水流方向；河口（下游端）画箭头。**汇入口 = 河口** |
| **分段** | 单段 | 点按钮，再点该段**中间顶点**，切成两段：同一条河、河名保留、各自设段名与水量 |
| **删除** | 单段 | |

**自动认父（两条路都行）**：

1. 画支流时让**终点落在已有河上**（12px 内自动吸附）→ 收笔时自动记为它的支流，等级自动定为"上一级 +1"；
2. 已经画好的：选中它 →「指定…」→ 点上级河道的线。会做**环检测**，不允许 A 当 B 的支流同时 B 又是 A 的支流。

**端点只有一套逻辑**（2026-11-12 合并）：以前"汇入/岔出/入海/入湖"是四套按钮、四条代码路径，
`[已证实]` 结果是 —— 运河端口不会切模式、湖岸要回列表找、单位错了两处（屏幕 px 与世界 px 混用）。
现在统一成 `pickTarget()`（在所有可用点里找最近的一个）+ `attachTo()`（把某一端接到目标上），
`kind` 由"这是不是河口端"推出来。加新目标类型（比如渡口、井）只需在 `pickTarget` 里加一行。

`[判读]` 「河名在河上、段名与水量在段上」是有意的：一条江的水量沿程变化（上游窄、下游宽），
而它在玩法里仍是一条整体（航运、漕运、渡口都按整条河结算）。

### 2.1.1 工具栏布局（2026-11-11 改版）

按钮不再全堆左上角：

| 位置 | 内容 |
|---|---|
| **左侧竖条** | 四个模式：河流 / 湖泽 / 海岸 / 选择 |
| **顶部横条** | 等级（干/一/二/运）、撤销重做删除简化、全图、图层 |
| **图层浮层** | 参考图、美术底图、城邑，以及各等级/湖泽/海岸的显隐 |

等级按钮只在「河流」模式下可用，其他模式自动变灰。

**画湖泽**：选「湖泽」→ 沿水体边缘点一圈即可，**不要求碰河**，原地画一个也行。

- 中间点**一律不吸附**，形状完全由手绘决定；
- 只有**首尾两点**在离河道 8px 内才会借用河道顶点，且位移超过 25px 就不借（防止把湖形拽变形）；
- 收笔方式三选一：**点回起点附近自动闭合** / 双击 / 回车；
- **终点吸附更灵敏**：起点已经落在河上时，终点对**同一条河**放宽到 45px 自动吸回；
  否则对任意河 10px。这样"点一下起点、绕一圈、在河边随便一点"就能收口；
- **河网图怎么建**：①同一段内相邻点 ②同一条河的分段端点距 ≤400px 视为接续
  ③不同河的端点吸到最近的异段顶点（≤14px，即河口/运河口）——三者构成一张图；
- **跨分段的河也认**：淮水切成 r003/r011 也能接起来；
- **起笔优先认河**：同一条河两岸各画一个湖时，第一个湖的沿河边界**本身就压在河道顶点上**，
  两个目标距离相等。所以画湖泽时起笔一律**优先吸附河道**（`pickTarget(..., 'river')`），
  否则会被已有湖的岸抢走、第二个湖就用不上"沿河闭合"了；
- **双击收笔那一下也算终点**：双击不会加点，但落点会当作收口位置参与吸附；
- **闭合边沿河网走（可以跨河）**：首尾都挂在河上时，在整个河网里跑最短路找一条通路，
  路径可能经过多条河（A 河 → 汇口 → 干流 → B 河），这就是湖的天然边界；
  只有两处之间确实没有连通水路时，才退回直线闭合（湖泽照样生成，只是 `arc` 为 null）；
- **顶点可拖**：选中湖泽后显示手绘顶点，拖动即可改形状；拖端点时若离原河道 25px 内，
  会重新吸回那条河，闭合边的河道段随之重算（`drawn` + `arc` 两个字段，`pts` 是派生的）；
- 记下接河位置（`onRivers`）。地图上按水体填充。
- **湖名**：选中湖泽后右侧出现「选中湖泽」面板，填湖名即可；画布上按多边形质心标注，
  地图（`map.html`）里以斜体蓝字显示。

**图层状态会记住**：参考图/底图/城邑、各等级与湖泽/海岸的显隐都存在浏览器里，
下次打开保持原样（和折叠状态一样）。

### 2.1.2 操作衔接（2026-11-12 打磨）

原则：**做完一件事，光标和模式就该落在下一步上**，不要让人回头找按钮。

| 动作 | 之后自动发生 |
|---|---|
| 画完湖泽 | 切到**选择模式**，湖泽被选中，**湖名输入框获得焦点并全选**，直接打字即可 |
| 画完海岸线 | 切到选择模式并选中它（可立即删除或看点数） |
| 点「指定… / 分段」 | 先切到**选择模式**再等你在画布上点——否则画线模式下点画布会变成又画一条河 |
| 在名字输入框按 Enter | 失焦并回到画布，快捷键恢复可用 |
| 点画布 | 若输入框还有焦点，先失焦；顺手收起图层面板 |
| 切换模式 | 未完成的草稿自动取消（有提示），不会留半条线 |
| 点中河段 / 湖体 / 海岸线 | 直接选中它并打开对应面板——**不必回列表找**；河段优先于湖与海岸 |
| 点空白 | 清空所有选中 |
| `N` | 跳到当前选中对象的命名框（河 → 河名，湖 → 湖名） |
| 选中海岸线 | 显示顶点，**可拖动改形**；岛屿首尾联动；接在岸上的河口跟着走 |
| 运河端口的「指定…」 | 与普通河同一套：河道线 / 湖岸 / 海岸线都能接（接海岸即出海口） |
| `Esc` | 取消草稿 + 清空所有选中，回到干净状态 |

`[判读]` 这几条都是为了一个目标：**画的时候手不离鼠标、不离开画布**。
每多一次"切模式 → 去列表里找它 → 点输入框"的往返，一条河就多十几秒。

### 2.2 交汇处怎么画、怎么改

三条规则，都是为了「支流看起来是汇入干流，而不是戳在干流上」：

| 规则 | 做法 | 为什么 |
|---|---|---|
| **父压子** | 绘制顺序按层级排序：支流先画、干流后画 | 支流末端的圆头会被干流盖住，交界处干净 |
| **河口定父子** | 只有**河口端**接上别的河才算支流；上游端贴到邻河只是"同源" | 沙水与颍水同源，曾因此被错挂成颍水的二级支流 |
| **抓得到交汇点** | 顶点命中优先级：**选中段 > 层级更深 > 更近** | 交汇点与干流顶点重合，否则永远抓到干流，支流端点"挪不动" |
| **父动子动** | 任何几何变化后调用 `syncChildren()` | 干流节点被拖动/简化/切分后，支流端点自动跟到新的接点 |

**拖动交汇点**：选中支流 → 直接拖它的端点 → 会**沿上级河道滑动**（自动投影到最近的上级顶点），
而不是把它拽离干流。要真正脱离，用「上级：断开」。

**切分/简化父段**时子段的处理：

- 切分：切点之后的子河自动改挂到后半段，顶点序号同步平移；
- 简化：先记下接点坐标，简化后重新找最近顶点；
- 删除：子河的 `parent` 置空，不会留下悬空引用。

`[判读]` 这三条本质是同一个要求：**河网是图，不是一堆独立折线**。
编辑器必须在每次改动后维持「端点 = 上级的某个顶点」这个不变量，否则一改就散。

**画法建议**：先把干流画完，再画一级支流，起点或终点尽量落在干流上——
描迹器会自动吸附并建立父子关系，右侧列表会按河网树缩进显示。

图层开关：河道参考图（`base_rivers.png`，红蓝水域）、底图（`../map-review/ditu.png`，默认关，避免每次启动解码 15MB）、城邑点。

打开时会先问是否恢复浏览器缓存；选取消则载入**随包数据**（`river_data.js`，由当前描迹文件生成）。

## 3. 数据格式

```jsonc
{
  "version": 5,
  "canvas": [9101, 8509],          // 与 nodes.csv 同一坐标系
  "exportedAt": "2026-11-12T00:00:00.000Z",
  "coasts": [                       // 海岸线（独立于河流）
    { "id": "c001", "closed": false, "pts": [[9106,2983],[9050,3010]] }
  ],
  "lakes": [                        // 湖泽（闭合水体）
    { "id": "l001", "name": "大野泽", "drawn": [[6000,4200],[6100,4250],[6050,4300]],
      "arc": { "path": [[6040,4290]], "from": {"seg":"r003","idx":42}, "to": {"seg":"r003","idx":50} },
      "pts": [[6000,4200],[6100,4250],[6050,4300],[6040,4290],[6000,4200]],
      "onRivers": [{ "at": 0, "seg": "r003", "idx": 50 }] }
  ],
  "segments": [
    {
      "id": "r001",                 // 河段 id（分段后每段一个）
      "river": "R001",              // 同一条河的分段共用一个 river
      "rank": 1,                    // 1 干流 / 2 一级 / 3 二级 / 4 运河
      "name": "长江",               // 河名（第一级），各段同步
      "section": "金沙江段",         // 段名（第二级），可空
      "water": 3,                   // 水量 1–5，按段；唯一决定线宽
      "flow": 1,                    // 1 = 沿 pts 顺序流（末点河口）；-1 = 反向（首点河口）
      "links": [                    // 端 → 河 的连接；普通河最多 2 条（河口+源头），运河 2 条
        { "at": 60, "kind": "mouth",  "river": "R007", "seg": "r012", "idx": 45 }
      ],
      "parent": {                   // 语义上级（树与等级用）；运河恒为 null
        "river": "R007", "seg": "r012", "idx": 45
      },
      "pts": [[3000,3000],[3200,3100],[3400,3200]],   // 画布像素
      "joins": [                    // 几何吸附痕迹
        { "at": 0, "seg": "r012", "idx": 45 }
      ]
    }
  ]
}
```

- 每条河段**独立记录**，不做合并；怎样分段由画的人决定。
- `river` 相同 = 同一条河：**河名**对整条河生效，**段名 / 水量**各自独立。
- `links` 是「端 → 目标」的连接表，`at` 为 0 或末点索引；`kind` 只有三种取值
  （`mouth` / `branch` / `sea`），目标类型看字段：有 `river` 是河道、有 `lake` 是湖岸、有 `coast` 是海岸线：
  - `mouth` **河口端**：接河道构成父子关系（`parent` 取它），等级按它推导；接湖=入湖、接海岸=入海则无 `parent`；
  - `branch` **源头端**：接河道=岔出（分水/同源，**不构成父子**）、接湖=出湖。
- 没有链接的端就是**天然源头**，可以任意拖动；有链接的端拖动时会沿对方滑动。
- **运河**两端都可连（不区分汇入/岔出，也不进支流树）。
- 接湖 `lake`：`{at, kind, lake:"l001", idx:7}`。不产生 `parent`，等级需自己定（湖没有上下游方向）。
- 接海岸 `sea`：`{at, kind:"sea", coast:"c001", idx:12}`，任何端都能接（含运河两端）。不产生 `parent`。
- `parent` 是语义上的父子关系（支流 → 汇入的河），由 `links` 推导；**运河恒为 null**，
  这样它不会混进支流树，而是作为连接件单独存在。
- `joins` 只记几何吸附痕迹。
- `lakes` 是湖泽列表：`[{id, name, drawn:[[x,y],...], arc:{seg,a,b}|null, pts:[[x,y],...], onRivers:[{seg,idx}]}]`。
  **边界是多段拼接的**：`pieces` 是一个环，每段要么 `free`（手绘），要么 `river`
  （`from`/`to` 两个引用：段 id + 顶点序号）。`pts` 由各段按序拼接、相邻重复点合并而成，全部派生。
  `[已证实]` 这样才表达得了大云梦泽那种"三段湖岸 + 三段河岸交替"的湖。
  `drawn` / `arc` 是单段湖的旧字段，保留同步一份只为兼容。
  `[已证实]` 早先只存 `path` 快照，河一动湖岸就不跟着变——现在只认 `from`/`to`。
- `coasts` 是海岸线列表：`[{id, pts:[[x,y],...]}]`，独立于河流，可多条。
- `flow` 决定哪一端是河口：`mouthIndex = flow === 1 ? 末点 : 首点`。
  认父时只看河口端，所以**流向对了，支流关系就对了**。
- `rank` 由 `parent` 链推导：无父 = 1，父为 1 级 = 2，父为 2 级 = 3，封顶 3；运河固定 4。
- 坐标保留 1 位小数，单位是画布像素（9101×8509）。
- `[已证实 2026-11-12]` **加新字段必须同时改 `migrate()`**：它负责把旧数据补成当前格式，
  早先只保留了 `river/seg/idx`，于是"接海岸"的链接一存一读就丢了（用户实际踩到）。
  现在的规则：`coast` / `lake` 字段原样透传，`kind:'sea'` 不被改写。

## 4. 水量 → 线宽

```text
线宽 = WATER_WIDTH[水量]          与等级无关
```

| 水量 | 1 极少 | 2 少 | 3 中 | 4 多 | 5 丰 |
|---|---:|---:|---:|---:|---:|
| 线宽（画布 px） | 2.4 | 3.6 | 5.2 | 7.4 | 10.0 |

颜色由等级决定（干 `#1b5e8c` / 一 `#2e86b8` / 二 `#5aa9cf` / 运河 `#8a5ea8` 虚线），
**粗细由水量决定**。描迹器里看到的就是地图上的效果。

`[已证实]` 为什么不能按等级定粗细：淮河是干流、长江支流是一级支流，
但淮河水量小于长江的支流——按等级定宽会把两者画反。这条是用户 2026-11-11 明确纠正的。

## 6. 下一步（用描迹数据反哺自动生成）

`parent` 已经在数据里，可以做自动生成做不到的四件事：

1. **河网拓扑**：父子链直接给出层级、Strahler 级数与上游汇流面积；
2. **校准自动算法**：用人工折线当 ground truth，量化自动提取的偏差（点到线距离分布），
   而不是继续靠肉眼判断"像不像"；
3. **河谷与流域**：干流两侧缓冲 → 河谷带；上游汇流面积 → 流域边界，用于"某城在某流域"；
4. **游戏口径**：河名用于奏报与条约文本（"决河于白马"），段名与水量用于具体工程
   （哪一段可通航、哪一段需要筑堤）。

`[判读]` 线宽问题到此闭环：粗细来自人给的水量，不再从像素宽度反推。

### 6.1 多个湖合成一个（布尔运算）

复杂水体（如大云梦泽）可以分块画完再合并，`tools/merge_yunmeng.py` 是一次性的做法示范：

1. 分块画：正片几块、负片（陆地/沙洲）单独画一块；
2. 栅格化求 **并集 − 负片**（`PIL` 填充，1 px = 1 世界像素）；
3. Moore 邻域追踪外轮廓 + 内洞，RDP 简化（0.8–1.1 px）；
4. 按"轮廓点是否落在河道顶点 2.4px 内"切成 `free` / `river` 段，
   太短的河段（<5 点或 <30px）并入 `free`，避免栅格噪声；
5. 写回数据，删掉分块。

`[判读]` 之所以用栅格而不是自己写多边形布尔：分块之间既有重叠又有包含，
手写 Greiner-Hormann 的退化情形（共线、自交、点接触）极易出错，栅格在这个尺度上误差 <1px。

## 7. 一次完整的画法顺序（推荐）

手工量很大（当前已画 48 段 / 47 条河 / 13 处湖泽 / 3 条海岸线），按这个顺序走最省事：

1. **先画海岸线**（左侧「海岸」）——大陆岸线一条，岛屿各一条并让首尾重合（会自动标闭合）；
2. **再画干流**（江水、淮水、济水…），水量按实际给 4–5；
3. **画一级支流**：从上游往河口方向画，**让河口端点落在干流上**（会自动吸附并认父）；
4. **画二级支流**：落在它的一级支流上；
5. **画运河**：两端分别接到两条河（运河的两端都是连接口）；
6. **画湖泽**：沿水体点一圈，点回起点自动闭合；首尾落在河上的会自动沿河岸闭合；
7. **补名字**：河名（整条河）→ 段名（分段后）→ 湖名；
8. 画完跑一遍第 5 节的四条命令出图。

**省事的几个点**（都是踩过坑之后加的）：

| 场景 | 做法 |
|---|---|
| 河从湖里出来/流进湖 | 端点直接点在湖岸上，会吸附并记 `lake` 链接 |
| 两条支流同源（一山分二水） | 源头端标「岔出」，只连不认父 |
| 一条河中途变宽变窄 | 在变化处「分段」，各段给不同水量 |
| 河流穿过图幅 | 端点照常画，不影响；海面只认海岸线 |
| 画错了 | `Ctrl+Z`；或删掉重画，比改快 |

## 8. 已知限制

- **湖链接不推导等级**：接湖的河 `parent` 为空，等级要手动设（湖没有上下游方向，硬推会错）；
- **跨河闭合走最短路**：A 河到 B 河如果有多条连通路，取几何最短的那条，可能不是你心里的那条——
  补上该补的汇口/运河，路径自然就对了；
- **海岸线只支持一条大陆岸线**用于推导海面（取最长的那条开放岸线），
  多条开放岸线时其余只作为线条显示；
- **海面推导依赖端点落在图幅边附近**，若岸线两端悬在图幅中间，闭合边会横穿画面；
- 描迹器是**单文件 HTML**，数据量大到十万点时命中测试会变慢（当前 2 万点无感）。
