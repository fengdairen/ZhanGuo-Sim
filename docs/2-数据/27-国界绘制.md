# 27 · 国界绘制（城池归属的来源）

> 状态：2026-11-13 首版可用。工具：`dist/map-review/border_editor.html`，
> 生成器 `tools/pipeline/make_border_editor.py`，数据 `data/map/borders.json`。

---

## 1. 为什么单独做一个

城池编辑器原本兼管归属，结果它既改坐标又改国家，职责糊在一起。
现在拆开：

| 工具 | 只管 |
|---|---|
| **国界绘制器** | 画边界线 → 组成疆域 → **决定每座城属于哪个国家** |
| 城池编辑器 | 城池的**位置、人口、等级**（归属只读显示） |

## 2. 边界线怎么画

和画河一样：点着拉线，但**两端必须落在已有几何上**——

- 海岸线
- 河流
- 湖泊边界
- 其他边界线

端点会自动吸附（16 屏幕像素内），吸附成功显示绿点，没吸附上会提示。
画的时候圆点会跟着鼠标走，看得出会吸到哪。

**点一次加一个顶点**，落下的是折线，不是鼠标轨迹；点与点之间自动连直线。
拖动鼠标只会预览下一段（虚线），不会偷偷加点。

- `Enter` / **双击** 收笔
- `Backspace` 退回上一个顶点
- `Esc` 整条丢弃

## 3. 从边界线到疆域（核心）

现实里没人会把国界画得首尾严丝合缝，所以**缺口由水系自动补全**：

1. 把海岸线、河流、湖泊、**其他**边界线的所有折线建成一张图（顶点=节点，线段=边）；
2. 把选中边界线的两端**焊**到这张图上（在折线上插入投影点，相当于在河的该处开个口子）；
3. 端点两两之间跑 Dijkstra，取最短路径作为补线；
4. 贪心匹配端点，保证每条边界线只用一次、每个端点只连一次；
5. 沿「边界线 → 补线 → 边界线 → …」走一圈，回到起点即闭合；
6. 闭合环就是疆域多边形，算面积、判城邑内外。

关键设计：**选中的边界线不参与补全**——否则"补线"就是那条线自己，永远闭合不了。

内置测试（`tools/smoke/smoke_border_editor.js`）用一个人造方形水系验证：

| 场景 | 期望 | 结果 |
|---|---|---|
| 一条线横穿方形 | 补成上半（800×300=240 000 px²） | ✅ 240 000 |
| 两条线 + 两侧水系 | 成 800×200 的带（160 000 px²） | ✅ 160 000 |
| 端点在带内/带外 | 内外判定正确 | ✅ |
| 端点悬空 | 明确报错，不生成鬼东西 | ✅ |
| 疆域内城邑 | 自动改归属 | ✅ |

## 3.1 画完还能改：拖顶点

边界线不是画完就钉死的。**选择模式**下：

- 点中边界线 → 显示所有顶点（橙圈）
- 按住**内部顶点**拖动 → 自由变形
- 拖动**端点**（首/尾）时受约束：只能吸附到海岸线 / 河流 / 湖泊 / 其他边界线上，
  吸不上就**还原**并提示；吸上了会同步更新这一端的记录
- **闭环**是例外：首尾本来是同一个点，拖哪一头两端一起动，不需要吸附
- 松手后自动做三件事：
  1. 受影响的疆域**重算几何**（闭环的按自身环重算，其余重新走水系补全）
  2. 疆域内城邑**重新判定**：新进圈的写入归属，跑出圈的清回无归属
  3. 边界线与 `ownership.csv` 一起存盘，并提示"疆域与城邑归属已跟随更新"

`[判读]` 重算发生在**松手**而不是拖动过程中：每帧跑一遍 Dijkstra 没必要，
而且拖动中途几何常常是坏的，算出来的东西没意义。

## 3.2 两种工具

左侧模式条有两个画线工具，规则不同：

| 工具 | 起止点 | 什么时候用 |
|---|---|---|
| **画边界** | **必须**落在海岸线 / 河流 / 湖泊 / 其他边界线上 | 大部分国界：一端接河、一端接湖 |
| **闭环** | 首尾自己咬上即可，**端点不受水系约束** | 一整块可以一笔围起来的地 |

闭环工具额外一条反向规则：**如果起点恰好落在已知点上，它拒绝生成**——
因为那就该用「画边界」，否则会绕开吸附逻辑，补全时找不到接口。

用法：点若干顶点，最后点回第一个顶点附近（12 屏幕像素内）即收环；
`Enter` 也能收环，`Backspace` 退点，`Esc` 丢弃。闭环边界线在清单里标「闭环」。

## 4. 两种成环方式

| 方式 | 做法 |
|---|---|
| **水系补全**（主） | 选几条不闭合的边界线，缺口交给海岸/河流/湖泊补 |
| **自身闭合**（辅） | 一条边界线首尾自己咬上（首尾距离 ≤2px），直接当疆域，不需要补全 |

`[判读]` 后者适合"这块地本来就四面环水、边界线可以一笔画完"的情形，
省掉一次匹配，也不会因为贪心匹配选出奇怪的补线。

## 5. 定国家、落归属

疆域生成后在右侧面板：

- **编号**：只读，系统给的（q1、q3…），删除后不回收
- **备注**：自由文本，写给自己看
- **国家**：从 `state.json` 的九国里选
- **应用归属**：把多边形内的所有城邑改成该国，并**直接写回 `data/map/ownership.csv`**
- **删除疆域**：里面的城邑**自动变回无归属**（只清本国名下那些），同样写回 CSV

`[已拍板]` 国家/地方二级归属暂时搁置——它牵涉别的线（宗族、封君），这一版只记国家。

写盘格式（新增 `faction` 列）：

```csv
city_id,owner,faction,note
n0000,ZHAO,,          ← faction 空 = 中央直辖
n0001,ZHAO,晋中宗族,
n0002,,,              ← 未归属
```

WPF 控制台按 `cells[0]/cells[1]` 读，多一列不影响；但它自己保存时会写回三列（丢 `faction`），
`[待验证]` 需要同步改 `CityTab.SaveOwnership`。

## 8. 现状与下一步

已可用：画线、吸附、补全、闭合、面积、内外判定、应用归属、自动存盘、撤销。

还没做：

## 地块模型（2026-11-14）

疆域不是"一国一块"，而是**地块**：每块独立成环，各自指定**国家**与**地方**。
一个国家可以有多块（含飞地），彼此不合并。

舆图上的表现：

- 同一国家的多块地块**只画外轮廓**：先把同国所有地块描一遍边，再把地块内部擦掉，
  于是共享边被整段擦除，只剩合起来的外缘；
- 点击任意一块，**同国的所有地块一起高亮**（填充加深、轮廓加粗），
  右侧信息栏按国家汇总：块数、城邑总数、面积合计、地方势力列表。

`[判读]` 地块之间不做布尔合并：合并会产生复杂多边形与拓扑问题，
而"只画外轮廓"这个画法在渲染层就能达到同样观感，数据还能保持一块一记录、好改好删。

## 国名可以直接敲

地块面板的「国家」是一个**可输入的下拉**（`<input list>`）：

- 从下拉里选已有国家 → 用它的配色；
- **直接敲一个没见过的国名** → 现场新建一个国家（自动取一个未用过的色），
  立刻可用，提示「已新建国家「X」」；
- 自定义国家跟着 `borders.json` 一起存（`nations` 字段），
  舆图生成时会把它们和 `state.json` 里的九国合并，配色与国名照常生效。

`[判读]` 没有把这些新国家写回 `state.json`：那份文件是 WPF 控制台的权威状态，
由它管理九国的经济军事；这里建的只是**地图上的国名与配色**，两边职责分开。

## 选边界线

| 操作 | 效果 |
|---|---|
| 点一条线 | 只选它 |
| Shift + 点线 | 加选 / 减选 |
| 框选（空白处拖） | 替换为框内的线 |
| **Shift + 框选** | **在现有选择上追加**，可以一批一批加 |

`[判读]` 疆域常常由十几段线围成，一段一段点太慢；Shift+框选能"先框一片、再框一片"，
最后点「生成疆域」一次成环。

### 编号规则

- 边界线与地块都按「现有最大号 + 1」编号：删掉中间某条，新线不回收旧号
- 载入时自检：发现重复编号，第二条起自动改号并提示
- 2026-11-14 修过一次历史数据：`b026`、`q11` 各出现两次（旧的 length+1 写法所致），
  已分别改为 `b029`、`q13`

`[判读]` 撞号的表现很有迷惑性：两条线或两块地共用一个 id，看起来像"一块疆域被拆成两段"
或"两块疆域耦合在一起"，其实只是同一个键指向了两个对象。

## 地块不许重叠

生成地块时会拿新环和所有已有地块比一次：

- 顶点落在对方内部（离边 >1.5px）→ 判为重叠
- 两条边真正相交 → 判为重叠
- **仅贴边（相邻）不算重叠**

一旦重叠就拒绝生成，提示「与已有地块 q13、q14 重叠，请调整边界线」，
免得出现"一块地同时属于两个国家"。

应用归属时另有一道保险：环内若已有归属他国的城邑，**不覆盖**，并在提示里报数
（「37 个城邑已归入 齐；5 座城已属他国，未覆盖」）。

## 成环算法（2026-11-14 修订）

选中 N 条边界线后：

1. 把所有水系、**所有边界线**建成一张图；端点若落在某条线上，就在线上插入投影点
2. **端点互连**：8px 内的端点直接接上（零权重）
3. 端点两两跑 Dijkstra，得到代价矩阵
4. **最小权完美匹配**（位掩码 DP，端点 ≤18；更多则退回贪心）
5. 沿 边→补线→边 走一圈，闭合

两个容易踩的坑：

- **多线成环时不能把选中的线排除出图**：端点常常正好落在另一条选中线的中间
  （实测 0.23px），排除掉就变成孤立点 → 无法匹配。只有"单线闭环"才排除自身。
- **贪心匹配会配错**：先配最短的一对，可能把某个端点唯一的出路占掉，
  最后剩下 2 个配不上。改为最小权完美匹配后，18 个端点全部配上。
