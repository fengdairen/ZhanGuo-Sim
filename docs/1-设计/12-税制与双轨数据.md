# 12 · 设计讨论稿：税制、定额与双轨数据

> 状态：**待讨论，尚未实现**
> 起因：用户指出"正史的税率不是比率，而是按估算定比例、按比例收定额；而且皇上不是全知全能，真实数据与报表数据必须分开"。
> 本文把这条直觉形式化，并给出对现有数据层的最小改造范围。

---

## 1. 史料依据

| 出处 | 内容 | 说明 |
|---|---|---|
| 《孟子·滕文公上》 | "贡者，**校数岁之中以为常**。乐岁…多取之而不为虐，则寡取之；**凶年…则必取盈焉**" | 税率来自多年平均估算；收的是定额；**荒年也必须交满** |
| 鲁宣公十五年"初税亩" | 履亩而税 | 必须先丈量→评估→定额，税率与田籍绑定 |
| 秦汉田租 | 三十税一 / 十五税一 | 名义是率，实际上解趋向定额 |
| 明清"原额主义" | 岩井茂树等 | 财政以"原额"为基准，正额与实征脱节，中间是耗羡与陋规 |
| 黄仁宇《十六世纪明代中国之财政与税收》 | "缺乏数目字管理" | 中央对地方的真实数目长期无知 |

`[判读]` 所以"皇上不是全知全能"不是体验包装，而是制度事实。把它做进系统，是还原，不是设计技巧。

## 2. 六个量

一笔税从田里到国库，要经过六个量：

```
Y  真实产出      ← 天时、战乱、劳役
A  评估产出      ← 田籍/户册，滞后；只有清丈才更新
Q  应征额        ← Q = A × r，一旦定了就是定额
C  实征额        ← C = Q × e，差额是「民欠」
T  入库额        ← T = C × (1 − 侵吞)，差额是「官侵」
R  报表额        ← 地方官报给君主的数
```

### 2.1 三个差额，三种病

| 差额 | 名称 | 性质 | 解法 |
|---|---|---|---|
| Q − C | **民欠** | 百姓交不出（荒年、流亡） | 减税、赈济、清丈 |
| C − T | **官侵** | 收上来了没入库 | 监察、清洗、换人 |
| R − T | **信息租金** | 报了假数 | 查账、御史、密报 |

`[判读]` 三者必须分开。混在一起，玩家就学不会"该派御史还是该减税"。

### 2.2 关键性质

- **丰年**：Q 不变，多出的产出留在民间（或被地方浮收）
- **荒年**：Q 不变，收不上来 → 民欠累积 → 流亡 → 下期 A 下降
- **加派**：Q 提高，但 C 未必等比提高，且民心下降
- **清丈**：A 上升（隐田纳入），但阻力极大

这形成一个真实的财政陷阱：**加税短期未必增收，长期一定侵蚀税基。**

## 3. 数值示例（用鲁国现有数据）

现有表：税基 4989、税额 2000、效率 0.8、上税 1600。

按新模型重新解读：

| 量 | 值 | 说明 |
|---|---:|---|
| A 评估产出 | 4989 | 来自田籍，**灾害不改它** |
| r 名义率 | ≈40% | 2000 / 4989，是推算值，玩家不直接填 |
| Q 应征额 | 2000 | 定额 |
| Y 真实产出（荒年） | 3000 | 掉了，但 Q 不动 |
| e 征收效率 | 0.8 → 0.5 | 收不上来 |
| C 实征 | **1000** | 民欠 1000 |
| 侵吞 20% | 200 | 官侵 |
| T 入库 | **800** | 国库实际只增这么多 |
| R 报表 | **1100** | 地方官报"已征千一百" |

**玩家看到 1100，国库实际增 800。**

## 4. 双轨数据的架构选择

| 方案 | 做法 | 评价 |
|---|---|---|
| A | 真、伪两套状态都存 | ❌ 两份数据必然分叉；而分叉正是崇祯所有 bug 的来源 |
| B | 只存真实状态，报表是投影 | ✅ 推荐 |

### 4.1 推荐做法

```
Reported = Project(True, bias)
bias = f(该官清廉度, 该官权势, 监察力度, 地方富庶度)
```

**理由：单一真相才能回放、才能审计、才能回滚。**

### 4.2 关键原则：不确定性来自「参数未知」，不是「随机数」

如果报表只是 `真实 × 随机扰动`，玩家的最优策略就是"多试几次取平均"——这是赌博，不是治理。

更好的做法：

- 每个地方官有**真实的、稳定的**贪腐参数；
- 玩家不知道这个参数，但可以**调查逼近**；
- 派御史查账 → 缩小估计误差；换人 → 参数重置；清洗 → 一次性追回部分官侵。

这样玩家的决策是"**花多大成本获取信息**"，而不是"赌概率"。
而且规则可学——这正是本项目与崇祯的分野。

## 5. 对现有数据层的最小改造

现有 Excel 其实**已经接近**这个模型，只是名字不对：

| 现有字段 | 实际语义 | 建议改名 |
|---|---|---|
| 税基（C12） | A 评估产出 | `AssessedOutput` |
| 税额（C13） | Q 应征额（定额） | `Quota` |
| 效率（C14） | e 征收完成率 | `CollectionRate` |
| 上税（C15） | C 实征额 | `Collected` |

**需要新增的边：**

1. `Y` 真实产出（受天时/战乱影响，但**不改 A**）
2. `Arrears` 逋欠累积（民欠）
3. `Embezzlement` 官侵率（C → T）
4. `Reported` 报表投影（R）

**不需要推翻公式**，只是把"产出一路乘到收入"改成"产出 → 评估 → 定额 → 实征 → 入库 → 报表"。

`[判读]` 这一步做完，`备份.xlsm` 的定位就清楚了：**它是报表层的历史快照，不是真相。**

## 6. 对工作台的影响

需要新增三样：

1. **视角开关**：真实 / 报表（调试时都能看，正式游戏只给报表）
2. **估计区间**：报表不是点值，而是"户部估约八百万至一千万两"
3. **调查动作**：花时间/钱缩小误差

## 7. 待拍板的问题

1. **双轨覆盖到哪一层？** 只做财政/人口/军队，还是制度、民心也做？
2. **失真是乘法还是加法？** 耗羡按比例（乘法）、陋规固定额（加法），先做哪个？
3. **玩家如何逼近真值？** 只有御史，还是加上商路情报、世家私信？
4. **逋欠怎么收场？** 累积成债务后蠲免，还是转成流亡人口并最终引爆民变？
5. **判定修正要不要也分真假？** 地方官报"灾情严重"骗蠲免，修正项就是可欺骗的。
6. **税率还让不让玩家直接改？** 我倾向：玩家只能改「名义率 r」，Q 由系统算；改 Q 要走「加派」这种显式动作，且必须担政治后果。
