# 34 · 地图渲染事故复盘（2026-11-15）

> 一次持续十余轮的"修不好"，最终定位到 `evenodd` 填充规则。
> 这份文档记的是**过程教训**，不是技术结论——技术结论只有一个句子，
> 剩下的篇幅都在讲"为什么会拖这么久"。

---

## 一、现象

疆域编辑器里，同一块地块（`lu:86154`，鲁国，`#c0392b`，3 个洞）在不同位置渲染出**三种深浅**：

| 位置 | 实测 RGB |
|---|---|
| 曲阜西侧 | (202, 175, 152) 粉 |
| 曲阜 | (215, 182, 131) 黄褐 |
| 昌衍 | (215, 182, 131) |

而页面自己的日志显示：这些点**只命中 1 层**。

同一块地、同一层、同一种颜色，画出两种颜色 —— 说明问题在**填充路径本身**，不在数据。

## 二、真正的原因

Canvas 的 `evenodd` 规则按"穿越次数"决定填充。外环 + 多个洞时：

- 洞严格互不相交 → 结果正确
- **洞之间有重叠、或与外环共边/退化** → 奇偶计数翻转，
  本该透明的区域被填实，同一块地出现深浅不一的斑块

这块面有 3 个洞，来自河网切割，边缘存在重叠。

**修法**：不用 `evenodd`。

```
离屏画布上填外环 → destination-out 逐个擦洞 → 整张贴回主画布
```

验证：同窗口、同视角、`?probe=6100,4230,1.2`，三点取样从
`(220,210,150) / (202,175,152) / (215,182,131)` 变为一致的 `(233,219,184)`。

## 三、为什么拖了十几轮

### 3.1 先改后看（最致命）

整个过程没有观测手段，全靠猜：

```
用户报现象 → 我猜一个机制 → 改一版 → 让用户去试 → 还不对 → 再猜
```

期间猜过的机制：绘制顺序、透明度、洞算得不够全、缓存失效、
`evenodd`、`nonzero`……前四个都是错的。

**观测工具（探针）是最后才做的，做出来的第一分钟就定位了问题。**

### 3.2 自己引入的新 bug

| 改动 | 后果 |
|---|---|
| 加 overlay canvas 让高亮瞬时 | 底图整片白掉，回滚 |
| 填充改 `nonzero` + 洞反向 | 整块变淡，回滚 |
| `patchPath` 换成新实现后填 `evenodd` | 颜色反而全错 |
| `str.replace(pattern, ..., 1)` 打补丁 | 命中了 `deepLink()` 而不是 `pointerup()`，整轮白改 |
| `showFaction` 引用不存在的 `rFac` | 抛异常吞掉后续 `draw()`，被误判成"没刷新" |
| 按面积跳过渐变 | 错判，渐变无罪 |

### 3.3 把用户当测试机

每一轮都以"已修复，请刷新"结尾。用户被迫反复试、反复截图、反复描述。
**用户报的每一个现象都是对的**，错的是我没有去复现。

### 3.4 数据层的坑伪装成代码 bug

- 浏览器里开着的旧标签页，在磁盘清空后又把旧数据**自动存回**服务器
- 服务器重建舆图时**漏跑 `faces.js`**，导致舆图一直读旧的归属
- 认领存的是"种子点"，事后按坐标重新定位，边界附近必然跳到相邻小面

这三个都表现为"算法坏了"，实际是链路问题。

## 四、规则（以后照做）

### 观测优先

1. **看不见的东西不要改**。先做探针：能对指定点输出"叠了哪几层、每层什么颜色、最终什么色"。
2. 每个修复都要有**改前 / 改后**的数字对照，不能只说"应该好了"。
3. 取样要固定：窗口尺寸、视角、坐标全固定，否则两次测的不是同一处。

### 改动纪律

4. **一次只改一处**，不过就回滚，不在坏的版本上继续修。
5. 字符串补丁命中多处时，**按函数上下文定位**，不按首现。
6. 取 DOM 元素一律判空——一个 `null.textContent` 会静默吞掉后面的所有逻辑。
7. 缓存 key 必须覆盖所有影响像素的状态（选中态、数据版本、变换）。

### 测试观

8. **测试通过 ≠ 视觉正确**。合成几何的单元测试管不到渲染路径。
9. 回归用例要覆盖真实数据与真实绘制路径，而不只是算法。

### 数据链路

10. 清理数据要在**拥有内存状态的那一侧**做（页面内按钮），否则旧标签会写回。
11. 出图链路每加一个产物，都要检查服务器重建时是否跑了对应的生成脚本。

## 五、图形编程的具体坑（可直接复用）

| 坑 | 正确做法 |
|---|---|
| 带洞多边形用 `evenodd` | 离屏填外环 + `destination-out` 擦洞 |
| 拖拽与点击混判 | 记录 `pointerdown` 点，位移超阈值即视为拖拽 |
| 右键弹菜单 | `contextmenu` 里 `preventDefault` |
| 嵌套面挖洞 | 对**全部面**算包含关系，不能只在已认领的面之间算 |
| 认领归属 | 创建时绑面 id，不要事后按坐标重新定位 |
| 平面划分入射 | 求交 + 端点投影，容差只补浮点误差（≤2px） |
| 环去重 | 用完整顶点签名，不要用"面积 + 点数" |
| 面缓存 | key 必须含变换、尺寸、dpr、数据版本 |

## 七、一句话

不是算法不会写，是**在看不见结果的情况下反复改**。
用户负责观察、我负责改——这个分工是错的。
正确的分工是：**我先能看见，再动手**。
