## 0. 三十秒版

**《战国演义》**：一款单机的战国题材文字国策模拟游戏。
玩家扮演国君，用**自由文本写国策**；LLM 把国策解读成结构化变更，落到**五个数值层**上；结算由确定性代码完成，结果以奏报形式回给玩家。

一句话定位：**AI 负责理解与叙述，代码负责裁决与记账。**

当前状态（2026-11-11）：

- **M0 已完成**：数据层脱离 Excel，`ZhanGuo.Core` 纯 C# 公式，校验 **284 项全过、偏差 0**

- **下一步：M1** —— 回合推进 + 事件日志 + 回放，**仍然不接 LLM**

## 3. 项目长什么样

### 3.1 五层模型

| 层 | 内容 | 类比 |
|---|---|---|
| **经济表** | 人口/税基/税额/效率 → 收入；工程/军事/行政 → 支出；国库 | 模拟器 |
| **地图区** | 邑/城/都的归属、道路、关隘、地形 | 容器 |
| **军事层** | 部队编制、训练、补给 → **战场模拟器**（已开发） | 模拟器 |
| **政策树** | 17 项制度 × I–IV 级，本质是先秦的制度改革 | 修改器 |
| **势力层** | 每个 NPC 与派系的利益诉求、权势、态度 | 修改器 |

**关键分类（整个架构的地基）：**

> 模拟器（经济、军事）**必须守恒**，LLM 绝不能直接写；
> 修改器（政策、势力）本身不产数值，只产**系数**，这是 LLM 的主场。

### 3.2 系数总线（最重要的设计）

LLM 永远不输出结果，只输出对系数的驱动：

```
LLM：{ faction: "鲁国士人", attitude_delta: -15 }
   ↓ 规则表（确定性）
系数：execution_discount = 0.72
   ↓ 结算器
到达率 = 制度系数 0.55 × 执行折扣 0.72 × 护送 1.0 × 距离 0.85 ≈ 0.34
```

**价值**：玩家能看到 0.34，也能看到它由哪四个数乘出来。**规则可学，这是策略游戏的本质。**

### 3.3 一回合的结算时序（不可乱序）

```
① 收集国策 → ② 意图解析（LLM 只产提议）
③ 【读】势力层：上回合态度 → 本回合执行折扣
④ 【写】政策树：改革推进
⑤ 【写】经济表：收入 → 开支 → 国库
⑥ 【写】军事层：调用战场模拟器
⑦ 【写】地图：领土变化
⑧ 【写】势力层：依结果更新态度
⑨ 【写】延迟效果队列
⑩ 生成回执（LLM 只读结算结果）
⑪ 提交：事件日志 + 快照 + 哈希
```

详细理由见 `10-项目定义-五层架构与LLM职责边界.md`。

## 4. 崇祯是什么，我们学到什么

《历史模拟器：崇祯》（青干工作室，Steam AppID 4304230，2026-05-08 发售）是这个赛道的**直接先例**。

### 4.1 它是什么

玩家扮演崇祯，用自然语言写诏书，AI 推演大明的命运。
它是**三套子系统靠文本串联**：大臣对话 → 拟旨 → 诏书推演。
**对话不改数据，拟旨是唯一 API，推演是唯一写入点。**

### 4.2 它的商业结局（必须记住的数字）

| 指标 | 数值 |
|---|---|
| 团队 | 不到 10 人 |
| 首月销量 | 约 3 万份 |
| 首月流水 | 约 144 万元 |
| **退款后开发者实收** | **约 20 万元**（86% 被退） |
| 好评率 | 54%–56% |
| **次日留存** | **75.1%**，非工作日在线 7 小时 |
| 结局 | 6 月 25 日**本体转免**，改为 BYOK |

`[关键判读]` **产品是成立的，死的是定价。** 玩家第二天还回来，然后被 token 账单吓跑。

### 4.3 它的技术结构（对照用）

- 官方链路：意图解析 → 逻辑推演 → 数据更新 + 文本反馈，走 **function calling** 直接写字段。
- 单局 token 消耗达 **3000 万级**。
- 专家模式用「步进式状态机 + 底层数据库」，做到 98.7% 推演前提正确率、99.86% Function Call 匹配率——**他们知道正确答案，但付不起**。

### 4.4 它的七个结构性断点

指代绑定 / 幂等 / 状态机 / 记账方向 / 税率与收入无公式 / 跨期无载体 / 单轮幅度上限。

**根因：状态没有被当作一等公民。** 有 Plan、有 Diff，但 Validate 很薄、Apply 几乎不存在（对照 PDVA 范式）。

### 4.5 我们的差异化

> 不是"AI 会推演"，是"**AI 会推演，但规则是你能学会的**"。
> 崇祯的所有差评本质都是"我不知道为什么"。

## 7. 工程铁律（不要违反）

1. **模型不碰模拟器。** 经济与军事的数值只能由代码写。
2. **M0–M2 不接 LLM。** 先用假国策、假事件把流水线跑通，否则无法区分"模型错"还是"结算错"。
3. **Excel 是编辑期工具，不是运行期状态。** 运行期用 JSON/SQLite。
4. **结算是纯函数**：`Resolve(state, edict) -> (state', events)`，无副作用，可回放。
5. **变更单必须带 `assumptions` 与 `unparsed`**，不许静默丢弃玩家的话。
6. **国策要有幂等键**（`edict_id`）。
