# 08 · 结构分析：文游数据模板与推演瓶颈

> 对象：`备份.xlsm`（2026-08-16 最后修改）
> 定位：**结构分析**。搞清楚这套模板算什么、人工推演在哪一步被卡住、LLM 能接哪一段。
> 结论先行：**这套模板把"确定性"已经做完了，缺的只有"自然语言 → 输入格"这一层。而那恰好是 LLM 最擅长的。**

---

## 1. 这是什么

一套**"文游"（群文字游戏）的数据后端**：

- 载体：QQ 群，玩家用文字写"国策"。
- 角色：一名真人**推演者**（裁判 + 系统）。
- 工作：读所有玩家的国策 → 判断后果 → **手工修改这份 Excel** → 写回执。
- 痛点：全流程串行、单点、无法并行，所以"马力全开"跑不动。

`[判读]` 这其实是**人肉版的崇祯世界引擎**——只不过崇祯把"判定"交给了模型，这套把"判定"交给了人，把"记账"交给了 Excel。

---

## 2. 物理结构

| 项 | 内容 |
|---|---|
| 工作表 | 10 张：9 个国别表（鲁/齐/宋/魏/韩/赵/秦/越/楚）+ 1 张「备用页」 |
| 单表尺寸 | A1:AP269，42 列 × 269 行（实际用到约 48 行，其余为预留） |
| 公式 | 全表 330 个 |
| 输入格（常量） | 每国约 **330–390 格**，9 国合计约 **3300 格** |
| 宏 | 每表 3 个按钮：`算账` / `+` / `-`；VBA 模块为辅助工具，不承担规则判定 |
| 保护 / 隐藏 | 无 |
| **回合 / 年份字段** | **不存在** |

`[判读]` 最后一行是全文最重要的发现：**表里没有时间**。回合只存在于推演者脑中和群聊记录里。

---

## 3. 数据模型逐块拆解

每个国别表是同一套版式，分四个区块：

```
行 4–21     国力与财政总账
行 25–37    军队表（6 个固定槽位）
行 42–199   人群与产业表（人口→产值→税基）
列 AA–AH    制度表（17 项 × I–IV 级）
```

### 3.1 国力四指标（B5、D5、E5、F5、G5）

| 格 | 含义 | 作用 |
|---|---|---|
| B5 | 人口（k） | `=SUM(H43:H199)`，由人群表汇总 |
| D5 | 预备兵力 | 直接输入 |
| E5 | 行政建设 | **行政开支的分母** |
| F5 | 军治清明 | **军事开支的除数** |
| G5 | 官僚腐化 | **总税收的折扣** |

`[判读]` 三个系数各控制一条公式的走向，是精简而有效的设计：**腐化扣收入，行政建设压成本，军治清明压军费**。

### 3.2 财政链条

```
税目/税基    行 8  /  行 10   （每国 2–5 个税种，可以是"传统鲁地""平陆占领区"这类地理/人群标签）
税基数值     行 12            = SUM(产值区间)   例：C12 = SUM(L43:L45)
税额         行 13            直接输入          例：2000
效率         行 14            直接输入          例：0.8
─────────────────────────────────────────────
上税         行 15            = 税额 × 效率
总税收       C16             = SUM(C15:K15) × (1 − 腐化)^0.5
```

支出侧：

```
工程开支     行 16–17   负数   例：-80 / -40
军事开支     C18        = SUM(维护费 N26:N37) / (1 + 军治清明)^0.5
行政开支     C20        = (都×12 + 城×10 + 邑×6 + 人口×0.8) / 行政建设^0.6
─────────────────────────────────────────────
总结余       E20        = SUM(E16:K19) + C16 − C18 − C20
国库         H20        直接输入（存量）
```

**实测（当前存档）：**

| 国 | 总税收 | 军事开支 | 行政开支 | 结余 | 腐化 |
|---|---:|---:|---:|---:|---:|
| 鲁 | 2218 | 635 | 1422 | +111 | 0.20 |
| 齐 | 5154 | 1526 | 4675 | +333 | 0.30 |
| 魏 | 6138 | 1458 | 5136 | +204 | 0.22 |
| 楚 | 6819 | 823 | 6081 | +635 | 0.30 |
| 赵 | 4518 | 1011 | 3474 | **−7** | 0.30 |

`[判读]` **行政开支是主要财政压力**，普遍是军费的 1.5–7 倍。这是很强的设计取向：养官比养兵贵。
`[判读]` 赵国结余为负（−7）却照常存在，说明**模板没有强制"国库不可为负"的不变量**。

### 3.3 军队表（行 25–37）

6 个固定槽位，每槽 2 行合并：中军 / 上军 / 下军 / 新军 / 独立骑兵 / 水师。

| 列 | 字段 |
|---|---|
| C–F | 步卒 / 甲士 / 辅助骑兵 / 战车（数量） |
| G | 训练度 |
| H–J | 驻地 / 统帅 / 备注 |
| L–N | 战备等级 / 补给等级 / 维护费 |

维护费公式：

```
N = (步×60 + 甲×150 + 辅骑×180 + 车×300) × √(1 + 训练度/100) × √战备 × 补给
```

`[判读]` 训练度、战备、补给都是**开方后相乘**——收益递减，且三项互相独立。这是个相当讲究的军队模型，不是简单加减。
`[判读]` 槽位固定 6 个，新建部队只能"占用"未建设槽位（备注写"未建设"），**不能动态增删**。

### 3.4 人群与产业表（行 42–199）

| 列 | 含义 | 公式 |
|---|---|---|
| C–F | 都 / 城 / 邑 / 野地（数量） | 输入 |
| G | 找补 | 输入（人工配平用） |
| H | 人口数 | `= C×120 + D×60 + E×30 + F + G` |
| I | 产业开发 | 输入（0–1） |
| J | 户口建设 | 输入（0–1） |
| K | 产业基数 | 输入（多为 12） |
| L | 产值 | `= H × I × K × √J` |
| M / N | 核心城市 / 人口类型 | 标签 |
| P/Q/R | 都/城/邑 的人口权重 | 120 / 60 / 30 |

`[判读]` 这是**投入产出式**的经济模型：人口 × 开发度 × 基数 × √户口建设。产值再按税种分组求和，成为税基。
`[判读]` 权重 120/60/30 是**硬编码在 P/Q/R 三个单元格**里的，不在公式里——改一处就能改全表，这是好设计。
`[判读]` 但税基引用是**写死的区间**（`C12 = SUM(L43:L45)`），一旦在中间插入人群行，所有税基引用都会错位。这是模板的结构脆弱点。

### 3.5 制度表（AA–AH 列，17 项 × 4 级）

17 个维度：军团架构 / 征兵与预备役 / 后勤运输 / 武备生产 / 工程建造 / 军功制度 / 军事训练 / 军事人才 / 军法军纪 / 土地制度 / 中央官僚 / 地方治理 / 法律体系 / 国家指导理念 / 行政人才 / 商业管制 / 贵族清退。

每个维度是 I–IV 四级，每级配一段描述（「备用页」存的是全量对照表）。
国表里：`AC` = 当前等级的描述文本，`AD` = 等级，`AE` = 改革点标记（`@`）。

`[判读]` 这是**离散化的软状态**——不是数字，是等级 + 文案。它必须靠"人工判断该升到几级"来推进，无法自动计算。
`[判读]` 「备用页」的等级描述**不完整**：IV 级普遍空缺，部分 II/III 级也只有编号没有文字。这意味着推演者升到高级时没有现成文案可抄。

### 3.6 国家时局（P/R 列，行 26–37）

形如"官办鲁缟 / 一部分鲁缟产业为官办，我们从中获益"——**事件名称 + 一句描述**，成对存放。

`[判读]` 这是全表最"软"的部分，也是唯一带有叙事的地方。它不参与任何公式，纯装饰 + 提醒。

### 3.7 判定修正（D18–H19）

一个**自由数值通道**：给每个"修正项"起个名，填一个数，直接进 `总结余`。

```
E18='判定修正'  E18='官办鲁缟'  F18='任国'  G18='倪国'  H18='玛瑙生意'
E19=80          F19=20         G19=20     H19=30
```

`[判读]` **这是推演者真正的"手"**。制度、民心、外交、灾害……所有无法用现成公式表达的效果，最后都倒进这里。
`[判读]` 但它没有来源记录：为什么是 +80？谁定的？第几回合的什么事？全部丢失。**这是这套模板最大的信息损耗点。**

## 4. 一回合里，人到底在做什么

把推演者的工作拆开：

| # | 步骤 | 性质 | 耗时来源 |
|---|---|---|---|
| 1 | 收集所有玩家国策（群聊翻记录） | 搬运 | 玩家越多越慢 |
| 2 | 逐条读懂国策，结合国势判断后果 | **判断** | 需要历史知识与上下文 |
| 3 | 把后果翻译成"改哪几个格子、改成多少" | **翻译** | 最容易出错 |
| 4 | 在 9 张表里改格子 | **记账** | 机械、易漏、易错位 |
| 5 | 自检一致性（钱够不够、兵从哪来、制度支不支持） | **校验** | 全靠人脑 |
| 6 | 给每个玩家写回执 | **叙事** | 写作成本 |

`[判读]` 六步里有 **4 步是机械劳动或翻译劳动**（1、3、4、5），只有 2 和 6 需要真正的判断与文笔。
**瓶颈不在"想不明白"，而在"想明白之后要手工搬 20 个格子"。**

---

## 5. 量化一下瓶颈

- 单国输入格约 330–390 个，9 国约 3300 个。
- 一条国策平均牵动 **5–15 个格子**，分散在 3 个区块、可能跨 2 张表（本国 + 制度页）。
- 改完必须自查：税基引用有没有错位、维护费有没有算进去、制度等级与描述是否一致、国库会不会变负。
- 9 个玩家 × （判定 + 翻译 + 改格 + 自检 + 回执）≈ 每回合 **2–3 小时的纯手工**。

`[判读]` 这就是"无法马力全开"的数学原因：**推演者是串行单线程，而工作量是 O(玩家数 × 国策复杂度)。**

## 6. LLM 能接哪一段

把六步按"该不该交给模型"重新分类：

| 步骤 | 交给谁 | 理由 |
|---|---|---|
| 1 收集国策 | 代码 | 只是搬运，不该占模型 |
| 2 判定后果 | **LLM** | 需要世界知识与语境理解，这是模型的主场 |
| 3 翻译成格子变更 | **LLM** | 自然语言 → 结构化参数，模型最擅长 |
| 4 改格子 | **代码** | 纯机械，必须确定性 |
| 5 一致性自检 | **代码** | 不变量检查，模型不可靠 |
| 6 回执文本 | **LLM** | 文笔 |

**分界线非常清晰：模型只碰"文本 ↔ 结构"，绝不碰"写入"。**

### 关键论点：这套模板比《崇祯》更适合 LLM

崇祯最大的结构性缺陷是**"税率与收入之间没有公式"**——模型改了税率，收入不会跟着变，只能靠模型"记得"去改，于是全错。

这套模板**没有这个问题**：

```
税额 → 上税 → 总税收 → 结余        全是公式，自动传导
人口 → 产值 → 税基 → 上税          全是公式，自动传导
维护费 → 军事开支 → 结余            全是公式，自动传导
```

`[判读]` 也就是说，**这套模板已经把"确定性"做完了**。模型只需要提供最上游的几个输入（税额、效率、都邑数、军队规模、制度等级、判定修正），下游全部自动。

这恰恰是崇祯做不到、而这套模板天然具备的东西。
**所以答案是：能，而且比原游戏更容易。**

## 7. 但模板有七个结构缺陷，会直接拖累 LLM

| # | 缺陷 | 对 LLM 的影响 |
|---|---|---|
| 1 | **没有回合/年份字段** | 模型无法判断"现在是第几回合"，也无法生成时间叙事 |
| 2 | **没有事件日志** | 上回合的国策不可追溯，模型拿不到历史，只能看当前快照 |
| 3 | **没有国策原文存档** | 输入本身不落盘，无法审计"模型是不是理解错了" |
| 4 | **判定修正无来源** | 数字有值无因，模型无法据此推理，人也无法复盘 |
| 5 | **税基区间硬编码** | 插入人群行会导致引用错位，模型改结构必炸 |
| 6 | **无负值校验** | 赵国结余 −7 照常运行，说明没有不变量约束 |
| 7 | **制度等级文案不全** | IV 级无描述，模型升级时无可引用文本，只能自己编 |

`[判读]` 第 1、2、3 条是同一个病：**这份表只有"状态"，没有"时间"。** 而 LLM 要做事，恰恰最需要时间线。

## 8. 如果真要接 LLM，最小改造清单

不是重写，是**加壳**：

1. **加一张《回合日志》表**：回合号、年份、国策原文、采纳的变更、判定修正来源。
2. **给判定修正加来源列**：`数值 / 事由 / 关联国策 / 回合`。
3. **把税基引用改成命名区域或整列求和**（`SUMIFS` 按人群标签分组），避免插入行错位。
4. **加一张《变更单》暂存表**：模型只往这里写结构化 diff，人工或脚本审核后再落到国表。
5. **加不变量检查**：国库不可为负、人口=都邑推导值、军队驻地必须存在于人群表的核心城市。

`[判读]` 前 4 条是"让模型有东西可读可写"，第 5 条是"让模型写错能被抓住"。加起来大概是一张新表 + 几条公式的工作量，不需要动现有版式。

---

## 9. 一句话总结

> 这套模板不是"不够用"，是**跑不满**。
> 它把最难的部分（确定性经济模型）已经做对了，缺的只是把国策文字翻译成输入格的那一层——
> 而那一层，恰好是 LLM 唯一真正不可替代的地方。
