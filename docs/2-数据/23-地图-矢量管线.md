# 23 · 矢量地图：从位图到几何的管线与数据

> 状态：**第一版可用**（2026-11-11）
> 产物：`dist/map-vector/map.html`（单文件，双击即开，不依赖任何位图）
> **2026-11-11 起河网改由人工描迹提供**（`docs/2-数据/25-河流描迹.md`），
> 本文的自动提取只保留作「未描河网」的淡色底衬。
> 本文记录**怎么把参考位图变成矢量数据**，以及过程中踩到的坑。

---

## 1. 为什么做这件事

原来的地图编辑器（`dist/map-review/city_editor.html`）是**位图底图 + 标点**：
底图 `ditu.png` 有 15 MB，缩放后糊，且**画面里的河流、海岸、行政线都无法被程序读取**——
它们只是像素。

改成矢量之后：

| 项目 | 位图底图 | 矢量 |
|---|---|---|
| 单文件体积 | 15 MB 底图 + 逻辑 | 319 KB 全包 |
| 缩放到 800% | 糊成色块 | 线条锐利 |
| 河流能否被程序查询 | ❌ | ✅ 折线，可算距离、可判"临水" |
| 海陆能否判定 | ❌ | ✅ 多边形，可 point-in-polygon |
| 换配色 | 得重做底图 | 改一个色值 |

`[判读]` 这是本项目第一次让**地图变成可计算的数据**，而不是一张画。

## 3. 一个必须纠正的判断：棕/黑线不是国界

最初的说明是"黑色是边界线"。逐像素核对后否定了这一条 `[已证实]`：

| 检验 | 结果 |
|---|---|
| 红 ∩ 棕（同像素） | **0** |
| 红 落在 棕 2px 内 | **93.8%** |
| 棕 落在 红 2px 内 | **100.0%** |

棕线是**每条河的描边（casing）**——红芯外面裹一层深色，所以与红线永不重合却
永远贴着。局部剖面目了然：

```
...........BBBRRRRRRRRRR
........BBBBRRRRRRRRRBBBB
.....BBBBBBRRRRRRRRBBBBB
...BBBBRRRRRRRRRRRBBB
```

**结论**：`底图河道湖泊.png` 里没有独立的国界层；棕线只能用作描边。
地图目前**没有国界**——等势力归属数据（城池属哪国）到位后再生成。

`[判读]` 这个坑差点让整张图出现"每条河都套一圈虚线国界"的荒谬结果。

## 4. 管线

```
底图*.png
  │ ① 颜色阈值 → 二值掩膜（全分辨率，不做降采样）
  │ ② 剔除湖岸红线（湖被一圈红线围着，那是湖岸不是河）
  │ ③ Zhang-Suen 细化 → 1px 骨架
  │ ④ 8 邻接走线 → 端点/交点之间的折线
  │ ⑤ Ramer-Douglas-Peucker 简化
  ▼
data/map/vector/*.json  ──→  tools/pipeline/order_rivers.py（线宽分级）
                         ──→  tools/pipeline/make_vector_map.py（生成 HTML）
```

### 4.1 五个踩过的坑（都会导致成品明显失真）

| # | 坑 | 现象 | 正解 |
|---|---|---|---|
| 1 | **降采样到 1/2 再细化** | 1px 线被 max 池化撑成 2px，8 邻接度直方图从"全是 2"变成"3、4 占一半"，细化卡死，走线碎成 2px 小段 | **全分辨率**处理；这几张图本来就是 1px 线条 |
| 2 | **8 邻接的斜向三角形** | 台阶拐角处，斜向邻居与两条正交边同时相连 → 拐角变成 3 度节点 → 每个拐角切一刀 | 斜向邻居若两条正交边都存在，**跳过这条对角边** |
| 3 | **只取红色做河线** | 红色水面在变窄处被描边盖住（红有 6.2% 远离棕），河网断成一串虚线 | 用**整条河的连续轮廓**做中心线 |
| 4 | **按"边"记访问** | 同一段骨架被走两遍，两条几乎重合的粗线叠在一起，放大后河中央露出浅缝 | 改为**按像素**记访问，每条链只走一次 |
| 5 | **把已知路径的段标成"闭环"** | 走线中途断开后仍标 closed，简化时把首点补到末尾，**凭空连出一条几百像素的直线**（最大 3024px） | 断开过的段绝不标 closed；相邻像素必须 8 邻接，出现跨越就地断段 |

`[已证实]` 坑 3 的量化证据：红色 469753 px、棕色 318011 px，红有 6.2% 远离棕，
正是这些地方断成虚线。整条河的连续轮廓只能取"红 ∪ 棕"。

`[已证实]` 坑 4/5 的量化证据：修正前区域内检测到近距平行对、以及 3024px 的
虚假直线；修正后最大跨度为 169px（属 RDP 在直河段上的正常表现），平行对 0 组，
河网从 325 段收敛到 183 段而覆盖不变（100%）。

**教训**：几何问题一定要用数据量化（段数、平均距离、最大跨度），
不能只看渲染图——PIL 渲染和浏览器渲染的锯齿不同，看图的结论经常是错的。

## 5. 河流线宽：怎么让主干粗、支流细

参考图里所有河一样细，矢量版加了分级。做法在 `tools/pipeline/order_rivers.py`：

1. **端点聚类**：走线会在交点处把折线切开，而同一交点的像素可能落在相邻几格。
   先吸附 4px 网格，再把 8px 内的端点并查集合并。
   （不聚类的话 4353 条边会退化成 3500 个孤立片段，汇流量算不出来。）
2. **定上下游**：从"河口"（距海岸 120px 内的端点，共 179 个）做 BFS 求图距离，
   距离大的一端是上游。
3. **累加上游长度**：按距离降序，`acc[v] = Σ(acc[u] + len(u,v))`。
   **必须是求和，不能取 max**——取 max 时所有河宽挤在 1.4–2.1，主干提拔不起来。
4. **映射**：`width = 1.3 + 3.2·log10(1 + acc/120)`，夹在 [1.3, 12]。

实测输出线宽 1.5–12.0，主 stem（黄河、长江）明显加粗。

## 6. 海与湖

| 对象 | 来源 | 方法 |
|---|---|---|
| 海面多边形 | `ditu.png` 的纯色海面 | 取最大连通域的外轮廓（降采样 1/2，1226 点） |
| 海岸线（描边） | `底图海岸线.png` | 细化 + 走线（939 段） |
| 湖泊 | `底图河道湖泊.png` 蓝块 | 连通域 + Moore 邻域边界跟踪（30 个） |

**湖的特殊处理**：每个湖都被一圈红线围住，那是湖岸不是河流。所以先把蓝块膨胀 3px，
把这些红像素从河网里剔掉，湖岸改由湖多边形自己的描边负责。
否则湖面上会压着一圈多余的"河"。

## 国界疆域层（2026-11-13）

舆图直接读 `data/map/borders.json` 的 `realms`，与描迹数据同源。

绘制顺序（关键）：**疆域面 → 海 → 河流 → 湖泊 → 海岸线 → 城邑**。
国界压在河网**下面**，所以两国以河为界时，河道仍然完整可见，不会被国界盖掉。

三层画法：

| 层 | 做法 | 参数（屏幕像素） |
|---|---|---|
| 面底色 | 国家色 10% 填充 | — |
| **内侧渐变** | 裁剪到面内，同一圈路径用递减宽度叠描 8 次，透明度累加成由边缘向内的色带 | 带宽 24 px |
| 边界线 | 整圈 `Path2D` **一次描边**，宽度恒定 | 2.4 px |

`[判读]` 边界不能按"段"逐条描，那样宽窄会随线段方向与接缝变化，出现一节粗一节细；
整圈一次 `stroke()` 才是均匀的。渐变用叠描而不是 `createLinearGradient`，
因为渐变得沿着多边形边缘走，线性渐变做不到。

## 自动重建（2026-11-13）

现在**不需要手动跑 `重建地图.cmd`**：

- 服务端在 `map.html` 被请求时，比较 `river_segments.json / borders.json / nodes.csv /
  regions.csv / ownership.csv / state.json` 的 mtime 与 `map.html`：
  源文件更新过就先跑一遍四步管线，再把这个页面发出去；
- 页面每 3 秒问一次 `/api/version`，发现源数据变了就自己 `location.reload()`。

于是流程变成：**描迹器/国界绘制器改完 → 切到舆图（或它已经开着）→ 自动是新图**。

`重建地图.cmd` 保留为**离线/导出**用途（不连服务时生成一份带数据的静态 HTML）。

## 标注与观感规则（2026-11-13）

满屏小字是舆图最刺眼的问题，改成分层 + 避让：

| 层 | 规则 |
|---|---|
| 城名 | 缩放 <20% 只显示**都**；<46% 加**城**；更大才显示**邑**。全部过同一张避让网格（110px 单元格，四周各留 2–4px） |
| 河名 | 按**水量 → 长度**排序，低缩放只保留前 16 条，20% 前 40，35% 前 90，60% 以上全显；同样过避让网格 |
| 湖名 / 部族名 | 同上，优先级低于城名 |
| 国号 | 不常显：点击地块才在信息栏显示 |
| 城池点 | 半径随缩放放大（`min(2.0, max(1, 缩放/0.22))` 倍）；**都**的基半径 3.4、外环 5.2，比原来收敛 |
| 国界线 | 国家色**压深 45% 再描**，否则蓝国家（齐、越）的国界会和河流撞色 |

深链：`map.html#n0231` 定位城池，`map.html#x,y,缩放` 定位任意坐标。

`[判读]` 国号是"面"的标签，不是"点"的标签：它只需要在整幅图的尺度上可读，
一旦放大到看城池，它就是噪音，所以按缩放显隐比一直显示更合适。

### 疆域层：栅格连通域做内侧渐变

路径级的"并集轮廓"在数据不规整时会碎：两块地分两次画，同一条界上的顶点采样不同，
按端点比对匹配不上，就会出现"一国好几个闭环"。所以改成栅格：

1. 把同国所有地块填成一张遮罩 A（evenodd）；
2. B = A 的高斯模糊版；
3. A 减去 B → 只剩**紧贴国界的一圈**，且由边向内自然淡出；
4. 用 `source-in` 把这一圈染成国家色。
