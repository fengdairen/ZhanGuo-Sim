# 53 · 结构分析：崇祯的判定逻辑与数据流

> 定位：**纯结构分析，不是设计方案。**
> 目标是把《历史模拟器：崇祯》"一道诏书怎么变成数据变化"这条链路拆到可以复述的程度。
> 后续你把数据层给我，我们就用这份结构做**映射与差距分析**。
>
> 标记：`[已证实]` 有官方/补丁/玩家实测佐证；`[推测]` 由现象反推；`[待验证]` 需实测。

---

## 1. 系统的三个子结构

崇祯不是"一个 AI"，是**三个职责不同的子系统**，靠文本通道串联 `[已证实]`：

| 子系统 | 职责 | 输入 | 输出 | 是否改数据 |
|---|---|---|---|---|
| **A. 对话系统**（廷议/私聊） | 扮演大臣，产出立场与建议 | 人设 + 官职 + 对话史 + 奏疏/诏书 | 对话文本 | ❌ 不改 |
| **B. 拟旨** | 把讨论收敛成一段可结算的文本 | 对话 + 玩家输入 | 诏书/拟旨文本 | ❌ 不改 |
| **C. 诏书推演** | 解析意图、推演后果、更新数据 | 诏书文本 + 当前状态 | 叙事 + 字段更新 | ✅ 唯一改数据的地方 |

**关键结构特征：A 与 C 之间没有共享上下文。**
玩家原话："诏书推演不知道你和大臣聊过什么，拟旨里没有就是不存在。"

`[判读]` 这是刻意的**信息瓶颈**设计。它带来两个后果：
1. 防止对话中的随口一说污染世界状态（避免"聊崩"）。
2. 玩家必须把"我要干什么"写成正式文本——这正是玩法张力的来源。

`[判读]` 换句话说：**拟旨文本 = 这个系统的唯一 API**。所有结算都从这段文本进入。

## 2. 一回合内的实际时序 `[推测，与所有证据自洽]`

```
① 回合开始
   ├─ 结算上回合遗留的延迟效果（欠饷、工程进度、灾害恶化）
   └─ 生成奏折/奏报（待办队列）
② 玩家阅读奏折（信息获取，可能失真）
③ 召大臣廷议 / 私聊（子系统 A）
   └─ 产出建议，可"采纳进诏书备选"
④ 玩家拟旨（子系统 B）
⑤ 颁布 → 进入推演（子系统 C）
   ├─ 意图解析
   ├─ 逻辑推演（在"数千维度"上）
   └─ 输出：叙事文本 + 函数调用（字段更新）
⑥ 后端应用更新（0.5.2 起有"本地判官"兜底）
⑦ 状态落盘
```

`[推测]` ①的"延迟效果"是否真的是确定性推进，存疑——因为玩家实测反馈"AI 没有能力进行跨期操作"，说明**跨期效果其实也交给了模型**，而不是账本自动推进。这是结构性缺陷，见 §6。

## 3. 字段结构：一份逆向出来的数据字典 `[已证实]`

### 3.1 三档类型

| 档位 | 内容 | 可变性 | 实现判读 |
|---|---|---|---|
| **枚举（写死）** | 派系、阶层、装备、兵种、科技 | 不可增删 | schema 里是 enum，模型无权扩展 |
| **实体（活）** | 大臣、军队、省份建筑 | 可增删改 | 列表型集合，有 id |
| **槽位（写死）** | 六部尚书、六殿大学士 | 数量固定 | `offices: slot → person_id` |

玩家原话："派系、阶层、装备、兵种、科技是写死的字段，改不了一丝一毫……你当然可以在上下文里加料，但上下文未必记得住。"

`[判读]` "上下文里加料但记不住" —— 说明枚举校验发生在**数据层**，写进 prompt 的"新兵种"不会被持久化。这正是"schema 是权威，文本不是"。

### 3.2 身份是弱类型的

- 大臣的**介绍**在引入时写定，之后不变。
- 大臣的**官职**是**纯文本字段**，每轮随诏书调整。
- 官职参与大臣的"自我角色认知"（对话时进上下文），但**介绍不进对话上下文**。

`[判读]` 这是一个很精细的设计：**人设（稳定）与身份（可变）分离**，且二者进入不同子系统的上下文。
`[判读]` 官职是文本而非外键 —— 这解释了一个已知缺陷：多人挂同一尚书衔时"推演容易出错"，因为槽位唯一性假设被打破。

### 3.3 财政：存量与流量是两套字段 `[已证实]`

| 类别 | 字段 |
|---|---|
| 存量 | 国库余额、内帑余额 |
| 流量（收入） | 田赋收入、旧饷收入、辽饷收入、杂项收入、其他内帑收入 |
| 流量（支出） | 军饷、赈灾、工程、赏赐等 |

**玩家实测出的三条硬事实：**

1. 抄家 = **存量**操作；要变成持续收入，必须显式要求改"杂项收入/其他内帑收入"。
2. 改税制后，**必须显式提醒模型调整田赋/旧饷/辽饷收入**，否则税率变了收入不动。
3. 改王田税率同理：**税率与收入不联动**。

`[判读]` 这说明：**存在"税率"和"收入"两个独立字段，中间没有公式**。
`[判读]` 更严重的是第 1 条：**存量→流量的转换不是自动的**，需要玩家在诏书里"教"模型怎么记账。这等于把记账责任推给了玩家。

### 3.4 单轮变更幅度有隐含上限 `[已证实]`

玩家："一次兴建太多的省份建筑，推演不认。"

`[判读]` 模型对单条指令的"工作量"有容忍上限；超出后不是部分执行，而是整体失效或质量下降。这更像**上下文/注意力预算**问题，而不是显式规则。

## 4. 判定链路：诏书 → 数据

### 4.1 官方描述的四段 `[已证实]`

> "意图解析 → 逻辑推演 → 数据更新与文本反馈"

展开：

| 段 | 做什么 | 产物 |
|---|---|---|
| 意图解析 | 从自然语言里识别"要干什么" | 隐含的动作列表（未公开格式） |
| 逻辑推演 | 在国库/军力/派系/民心等维度上推断后果 | 因果链 |
| 数据更新 | **函数调用**写字段 | 字段增量 |
| 文本反馈 | 生成奏报/叙述 | 叙事文本 |

`[判读]` 官方明确说"输出准确的函数调用"——所以走的是 **tool/function calling**，不是自由 JSON 解析。这意味着动作空间在代码侧是**封闭枚举**（开放的话没法定义函数签名）。

### 4.2 动作空间的结构判读 `[推测]`

从玩家的操作清单反推，函数签名大致是这几类：

| 动作族 | 参数 | 证据 |
|---|---|---|
| 财政调拨 | 账户 for、账户 to、金额 | 内帑/国库操作频繁 |
| 税制变更 | 税种、税率 | 需另调收入字段 |
| 赈灾 | 地区、物资、执行人 | 诏书范例 |
| 调兵 | 部队、目的地、路线 | 诏书范例 |
| 编练/裁撤/合编 | 部队、编制、银 | 玩家实测 |
| 任免 | 人、官职 | 官职是文本字段 |
| 刑罚 | 人、方式（下狱/抄家/处决） | 补丁日志 |
| 兴造 | 地区、类型、工期、银 | 省份建筑 |

`[判读]` 注意"赏赐将士→提士气""补充补给→提补给""训练"是**独立的动作族**，说明军队是有 `morale`/`supply`/`training` 三个以上子字段的实体。

### 4.3 "本地判官"是什么 `[已证实存在，职能待验证]`

0.5.2："默认启用本地判官"。
0.5.1："内阁票拟改为本地处理"。

`[推测]` 候选职能：
- (a) 把模型的自由文本输出**规整成合法函数调用**；
- (b) 对数值更新做**范围夹逼/合法性检查**；
- (c) 处理"票拟"这类规则性强的环节，不调大模型；
- (d) 降本——把一部分判定从云端挪到本地小模型。

`[判读]` 无论哪种，趋势是明确的：**判定权正在从"大模型自由裁量"回收到"本地确定性组件"**。这与 0.5.5 修"抄家不入账/支出误记收入"是同一件事的两面——**他们开始不信任模型记账了**。

## 5. 上下文结构（他们到底往 prompt 里塞什么）

这是最有价值、也最不透明的部分。从证据反推 `[推测]`：

### 5.1 进入诏书推演的上下文

```
+ 当前状态快照（国库/内帑/军队/派系/省份/大臣官职…"数千维度"）
+ 诏书/拟旨文本（唯一的玩家意图通道）
+ 历史摘要（长局靠摘要 + 检索维持）
- 大臣对话原文（明确不进）
```

### 5.2 进入大臣对话的上下文

```
+ 该大臣的人设（首次对话时详细展开）
+ 其官职（文本字段，参与"自我角色认知"）
+ 对话史
+ 奏疏 / 诏书
- 其"介绍"（原文：介绍不为其上下文）
```

`[判读]` 有一个微妙点：**大臣的介绍不进对话上下文，但官职进**。
这意味着大臣"知道自己现在是什么官"，但"不一定记得自己被写定时是什么人"。设计上可能是为了让大臣随官职漂移，产生"人变了"的效果。

### 5.3 记忆策略的代价

官方自述单局 **3000 万 token**。`[判读]` 这个量级说明：**历史几乎全靠"压缩摘要 + 检索"维持**，而不是结构化状态。
所以玩家感知到的"长局记忆漂移"，不是 bug，是**架构的必然结果**。

## 6. 结构性缺陷清单（判定的七个断点）

把补丁日志与玩家实测交叉，可以定位七个**结构层面**（而非偶发）的断点：

| # | 断点 | 表现 | 根因判读 |
|---|---|---|---|
| 1 | **指代绑定** | 抄错人；归附人物无法召见 | 自然语言 → 实体 id 的映射无强约束 |
| 2 | **幂等** | 重复抄家 | 无 `edict_id`，重放即重算 |
| 3 | **状态机** | 下狱后不认诏令；批准处决不执行 | 实体的 status 与"可执行动作"未联动 |
| 4 | **记账方向** | 抄家不入账；支出误记收入 | 模型填裸数值，无借方/贷方 |
| 5 | **存量/流量** | 税率改了收入不动 | 两套字段之间没有公式 |
| 6 | **跨期** | 摊销被当成一次性扣款 | 无"计划表"，跨期靠模型记忆 |
| 7 | **单轮幅度** | 一次建太多建筑推演不认 | 上下文/注意力预算上限 |

**注意 #5 与 #6 的性质**：它们不是"模型不够聪明"，而是**数据层没有为它们建模**。
模型再强也做不对，因为**系统里根本不存在"税率→收入"这条边，也不存在"分期"这个实体**。

### 6.1 一个推论：为什么"AI 没有跨期能力"

玩家原话："这种时候要果断倒退一回合重新推演，ai 没有能力进行跨期操作。"

`[判读]` 因为跨期效果**没有持久载体**。每回合模型只能看到"当前快照 + 历史摘要"，而摘要里不会精确记录"还有 8 期、每期 2.5 万两"。
所以正确解法不是换更强的模型，而是**在数据层加一个 `scheduled_effects` 表**。

## 7. 难度模式 = 判定强度旋钮 `[已证实]`

| 模式 | 差异 | 判读 |
|---|---|---|
| 硬核 | 取消开局保护，赤字、低权威、高腐败 | 初始状态更差 |
| 标准 | 保留"新君登基"效果 | 前几回合宽容 |
| 自由 | **降低部分系统检测强度**；地方官倾向字面执行 | **校验层被放宽** |

`[判读]` "自由模式降低系统检测强度"是极重要的证据：它证明系统里**存在一个显式的"检测/校验"层**，且其强度是可调的参数。
这与"本地判官"是同一个东西的两种暴露方式。

`[判读]` 换句话说，崇祯的判定链路至少有：
`模型提议 → 检测层（可调强度）→ 数据更新`。
我们此前以为的"模型直写数据"，其实中间隔了一层——只是这层当时很薄。

## 8. 与学术范式的对照（PDVA 映射）

把崇祯的结构映射到 *Orchestrated Reality* 的 Plan–Diff–Validate–Apply：

| PDVA 阶段 | 崇祯的对应物 | 差距 |
|---|---|---|
| **Plan**（切出有界上下文） | 状态快照 + 历史摘要 | 无"按动作相关性"裁剪，全量塞 → 3000 万 token |
| **Diff**（叙事 + Δ） | 叙事 + 函数调用 | ✅ 基本对应 |
| **Validate**（schema/权限/规则） | 本地判官 + 检测强度 | 薄；无权限模型；规则不完整 |
| **Apply**（原子提交 + 哈希） | 直接写字段 | ❌ 无原子性、无哈希、无回放 |
| **事件溯源** | 无（或极弱） | ❌ 读档曾误触发结算即为证 |

**结论：崇祯有 P、D，弱 V，几乎没有 A。**
它的所有长局问题，都能落到"V 太薄 + A 不存在"上。
