## 2. 文件与字段

### 2.1 `data/map/nodes.csv`（城邑）

| 列 | 含义 |
|---|---|
| `id` | 节点 id，`n0000` 起；编辑器新增的是 `x` 前缀 |
| `name` | 地名 |
| `kind` | `都` / `城` / `邑` |
| `x`,`y` | **地图像素坐标**（画布 9101 × 8509，左上角为原点） |
| `pop` | 人口，单位 **万** |
| `source` | 人口来源标记（`默认值` / `鲁·曲阜(都)` / `默认值 ×0.75 ×0.8` 等） |

### 2.2 `data/map/regions.csv`（部族）

| 列 | 含义 |
|---|---|
| `id` | `rg000` 起 + 编辑新增 |
| `name` | 部族名 |
| `x`,`y` | 中心点（文字标签位置，不是几何中心） |
| `pop` | 人口（万） |
| `note` | 备注（如"手工补充"） |

### 2.3 坐标约定

- 画布尺寸 9101 × 8509
- 两个导出层的画布偏移不同：`城池` 层 (635, 874)、`城池名称` 层 (512, 866)
- 现存数据已统一换算到**画布坐标**

### 2.4 `data/map/groups.csv`（人群库）

| 列 | 含义 |
|---|---|
| `name` | 人群名 |
| `note` | 简介——描述其文化、认知与政治倾向 |

初始只有一条：

```
无认同人口, 无确切的民族或国家认同，只认为自己是种地的野人
```

### 2.5 `data/map/populations.csv`（人口条目）

**人口不再是城池上的一个数字，而是一张表。** 一个城可以有多条人群记录。

| 列 | 含义 |
|---|---|
| `id` | 条目 id（`p00001` 起；编辑器新增 `u`/`t` 前缀） |
| `city_id` | 所属城邑或部族 |
| `group` | 人群名（引用 `groups.csv`） |
| `amount` | 数量，单位 **万** |
| `note` | 条目备注（可空） |

城池的**总人口 = 该城所有条目之和**（派生值，不再单独存）。

迁移结果：1094 条记录，全部为「无认同人口」，合计 2266.2 万。

**设计意图**：后续可把某城的部分人口从「无认同」划给「楚人」「秦人」「宋遗民」等，
从而支持"某地有多少万什么人"这种玩法级表达——征税、征兵、认同、叛乱都挂在这上面。

## 3. 人口口径

### 3.1 默认值（用户定）

| 类型 | 默认 | 说明 |
|---|---:|---|
| 都 | 30 万 | 后经 ×0.75 |
| 城 | 8 万 | 后经 ×0.75、×1.15 |
| 邑 | 2 万 | 后经 ×0.75、×0.8 |
| 部族 | 0.2–0.8 万 | 均值约 5200 人 |

### 3.2 已执行的两次调整

| 调整 | 内容 |
|---|---|
| 全图下调 25% | 城邑全部 ×0.75 |
| 分类调整 | 邑 ×0.8、城 ×1.15、都不变 |

调整后：都 675 万 / 城 421 万 / 邑 1139 万 = 2235 万。

### 3.3 有真实数据的人群

来自经济表（`state.json`）的 61 个"人群"，其中 **13 个能找到对应城池**并按下式分摊：

```
群总人口 ÷ (都×30 + 城×8 + 邑×2) = 缩放系数
该群的都 → 30×系数，城 → 8×系数，邑 → 2×系数
```

例（鲁·鲁人：1 都 1 城 11 邑，51 万人）：系数 0.85 → 曲阜 25.5 万、1 城 6.8 万、11 邑各 1.7 万。

其余 48 个群名是"地区"（河东、上党、汝颍…），找不到锚点，落回默认值。
**这是当前最大的精度缺口**，需要一张"人群 → 中心城"对照表（`data/map/group_anchor.csv`，61 行，待填）。

| `tools/make_pop_editor.py` | 生成人口编辑器（只有人口） |
| `tools/make_html_map.py` | 生成只读总览 |
| `tools/merge_editor_export.py` | 把编辑器导出的 CSV 合并回数据 |
| `tools/assign_population.py` | 人口初始分摊 |
| `tools/make_package.py` | 打包分发给协作者 |

### 5.1 两个网页工具（`dist/map-review/`）

| 文件 | 用途 |
|---|---|
| `names.html` | 批量改名，一题一屏，回车确认 |
| `map_editor.html` | 完整地图编辑器：改名 / 移动标点 / 新增删除 / **配置某城有哪些人群、各多少万** |
| `pop_table.html` | **人群库**：只定义"世界上有哪些人群"，每群一条简介 |

**分工原则**（用户明确要求）：人群库决定"有谁"，地图编辑器决定"哪个城有多少谁"。
人群库页面不出现地图；地图编辑器里不新建人群。

两者都支持 **「绑定本地文件（自动保存）」**：选一次 CSV 路径，之后改动 0.8 秒自动写盘，不需要手动导出。
（需要 Chrome / Edge 的 File System Access API）

## 6. 数据流向

```
城池.png ──检测──> nodes.csv（坐标+类型）
城池名称.png ──OCR──> 名称 ──人工勘误──> nodes.csv（名称）
state.json（经济表人群）──分摊──> nodes.csv / regions.csv（人口）
                    ↓
        编辑器 / 勘误页（人工修正）
                    ↓
             map_edited.csv ──merge_editor_export.py──> 回写
```
